# 《无尽虫潮》手机视野与虫潮可见性 PRD

> 版本：v1.0 · 2026-11-11 · **产品/技术方案规划，尚未修改战斗代码**  
> 优先级：M5.3（建议紧随 M5.2 无打断 XP 之后，早于三幕长局和新英雄系统）  
> 关联：[产品总纲](PRD_V2.md) · [Roguelite 三幕核心循环](PRD_ROGUELITE_CORE_LOOP.md) · [英雄武器系统](PRD_HERO_WEAPON_SYSTEM.md) · [路线图](ROADMAP_M6_M8.md)

## 1. 真实问题及代码依据

玩家在手机上反馈：**可视范围太小，虫子还没出现在画面里就已经被自动武器击杀**。这不是待证实的“可能不够爽”，而是**已反馈的可见性缺陷**。

2026-11-11 审查线上 M5.1 的相关实现：

| 事实 | 当前代码 | 设计后果 |
|---|---|---|
| 竖屏逻辑宽度固定 450，高度按手机长宽比扩展 | `src/main.ts` Phaser Game / viewportHeight | 长屏上下有余量，但左右视野仍只有 225 单位 |
| 相机直接跟随玩家，未设置 zoom | `GameScene.create()` startFollow | 玩家通常居中，横向可见面积受 450 宽度限制 |
| 基础步枪索敌距离 360 | `src/game/combat.ts` fireRange | 360 大于左右横向半屏 225，**射程可以覆盖不可见区域** |
| 普通敌人出场半径约 325–463 | `pressurePlan.spawnRadius` + `spawnEnemy` 额外 0–65 | 大部分侧向新生敌人出现在镜头外 |
| Boss 初始生成距离约 315 | `spawnEnemy('boss')` | Boss 可能从视野外开始受到远程武器攻击 |
| 四武器特殊攻击射程分别取 190、270、320 或 360，再乘以卡牌射程和武器等级调节 | `fireWeapon` | 远程加成进一步提高离屏伤害可能性 |
| 现有相机使用世界边界 2300×2300，跟随缓动 0.14 | `GameScene` | 地图边缘相机不一定让玩家处于画面中央，必须按真实可见矩形计算 |

**关键几何事实**：逻辑宽 450、默认缩放为 1 时，以玩家为中心的左右视野约 225；圆形索敌半径 360，即使无卡牌也可能在水平方向超过屏幕外沿 **135 单位**。如果相机缩至 0.72，半屏世界宽约 `225 / 0.72 = 312.5`，仍不能保证 360 的基础射程完全可见；不能靠单独固定 zoom 解决。

## 2. 产品目标

1. **虫潮先被玩家看到，再被武器大规模歼灭**。至少使侧向冲来的主要虫群能在屏内形成压迫与火力反馈。
2. **手机横向视野明显增大**，但机甲、普通虫、精英、子弹、危险预警仍然可辨认。
3. **武器射程属性仍然有价值**；不能以永久砍射程解决视野，避免破坏远程狙击和英雄级武器的特色。
4. 增加对虫潮方向、精英、Boss、场景目标的**提前感知**，但不使用遮挡中心战斗的大地图常驻界面。
5. 保留单指控制、自动射击、移动/展开的战术关系；不要求手动转镜头/拖动视角。
6. 玩家可以清楚看到“将要进入屏幕的敌人”及“被炮火打倒的敌人”，避免在不可见区域持续刷击杀数。

## 3. 推荐总体方案：动态宽视野 + 可见作战区 + 入场演出

### 3.1 第一步：手机画面横向扩容

- 推荐从 **portrait camera zoom 0.72–0.78** 开始实验，默认参考 **0.75**；最终按机型和可读性验证。
- 保持逻辑屏宽 450、按长宽比扩展高度；zoom 0.75 时**单侧横向世界半径约 300**，比现有 225 增加约 33%。
- 战场依然由相机跟随机甲，**不改变世界尺寸、玩家真实移动速度、射弹命中算法**；镜头缩放只改变所见面积。
- 机甲缩小会降低辨识度，须同步核对英雄轮廓、头部方向、肩部武器和精英提示。可对英雄特效/角色的像素尺寸做**局部补偿**，但不能只把玩家 sprite 放大导致敌人大小失衡。
- 动态/解锁视野仅作为后续可选能力：例如特殊精英和 Boss 预告期临时扩大至 0.68–0.72，平时平滑恢复；**不要在每次出现普通敌人时频繁拉伸镜头**。
- Zoom 变化须与 `Phaser.Scale.RESIZE` 联动，只影响相机 world view；固定 HUD 的尺寸、输入区域与选卡 DOM 不应随着 zoom 变小。
- 地图边界不能产生大面积无效空镜；相机在世界边缘可调整目标偏置，使有效区域占据更多画面。

### 3.2 第二步：明确“看得见才开始常规自动清怪”

对**基础普通武器**增加“屏幕边缘可见门槛”，而非盲目限制所有武器射程：

- 自动索敌的普通近身清怪，优先选择**真实相机可见矩形内**的敌人；建议在镜头边缘留 20–35 **屏幕像素**的可读边距才进入正常自动锁定。
- 已锁定、进入了屏幕的敌人，即使短暂跨出边缘也可保留 **0.2–0.4 秒锁定宽限**，避免边缘反复丢失目标；宽限过程中不应无限跨屏追踪。
- **远程专用武器（磁轨狙击、轨道炮、英雄级追踪武器）允许明确设计的离屏攻击**，但必须有短促的边缘方位提示、可追踪的弹道/打击反馈，以及单次强攻击的节奏控制。
- **电弧跳链、爆炸/火焰传播、召唤单位**可以越过屏幕边界造成合理的延迟伤害，但不应无限跨越战场，且离屏击杀要有明确频率上限或反馈。
- 不允许单纯因为镜头上端高而让水平方向射程无限缩短；按**可见矩形与真实敌人坐标**判定，而不是仅用圆形距离估算。
- **不以“屏内敌人杀不死就保持屏上”的伪机制改变血量**：首次可见门槛应作用于索敌/开火决策，而不是伤害无效化。

**定义**：`canAutoAcquire(target, cameraVisibleRect, weaponPolicy)`，默认需要目标进入当前屏幕的安全可读区域；有 `weaponPolicy.allowOffscreen` 的英雄/远距特种武器可例外。对于喷火锥形/范围爆炸，无需逐个检查弹丸所在屏幕；重点约束攻击**起始目标**和可感知反馈。

### 3.3 第三步：重新设计虫群登场

- 当前普通敌人按 325–463 的距离在玩家周围出生，缩小镜头后仍存在**左右方向刷在屏幕外**的情况。
- 改为依照相机视野矩形选择刷怪扇区或边缘可见过渡带，而不是只根据玩家圆形距离：
  1. 出场前 0.6–1.0 秒，在屏幕边缘对应方向显示简短“虫潮逼近”警戒/裂隙效果；
  2. 敌人在**可见区域边缘或刚刚进入视野的过渡区**出现，随后向玩家集结；
  3. 任何出生点不能直接贴近玩家、躲开预警也不能被新刷怪圈封死；
  4. 越到后期，更多虫群在同一可见方向**有编队地涌入**，而不是分散地随机瞬死。
- 避免“贴着相机边界突然凭空冒出”的违和：生长裂口/机械预警线 + 有明显的入场动画。
- 普通虫进入视野时保留短暂可辨的运动过程（建议目标 **≥0.4–0.7 秒**），这只是可见性目标，不能给小虫加永久无敌时间。
- Boss 和精英应当有更明显的远端方位/入场预警，并让玩家先辨认目标后承受强技能。

### 3.4 第四步：让新视野变成真正的战斗体验

- **机甲可读**：上方/侧向枪械挂架、脚步运动与能量核心不能缩到只剩小点；主机甲占屏宽度不宜过小。
- **虫潮密度**：玩家在多武器成型阶段应看到有序逼近的虫群，而不是击杀数在屏外飞涨。
- **武器命中轨迹**：前方 1–2 次穿透、雷霜连锁、散射引爆可以在视野内观察到主过程。
- **目标提示**：Boss/精英/虫巢节点位于屏幕外时，在屏幕边缘显示简洁方位标识，持续到目标进入屏幕；不依赖常驻小地图。
- **区域挑战**：后续多战区孵化巢出现时，允许从更远位置预告其存在，但正常枪口锁定仍优先屏内近身威胁。
- **警戒优先级**：濒死、自爆虫和 Boss 技能预警比远端入场指示优先级高，不能被武器光效遮挡。

## 4. 三套方案对比

| 方案 | 解决什么 | 主要代价 | 产品判断 |
|---|---|---|---|
| **A. 只把相机缩小** | 更多敌人可同时看到 | 机甲/虫子变小；远程索敌仍可能离屏 | 作为基础，但**单独不够** |
| **B. 只限制射程至屏内** | 离屏击杀显著减少 | 射程卡和狙击武器价值受损、边缘目标抖动 | 仅对基础自动索敌采用可见门槛 |
| **C. 镜头 + 可见索敌 + 虫群入场（推荐）** | 同时改善视野、压迫感与命中可读性 | 需要调整相机/出生/目标策略 | **规划默认方案** |
| D. 改成横屏 | 天然横向视野大 | 违反单手竖屏产品定位 | 不采用 |
| E. 加常驻小地图 | 知道屏外敌人位置 | 不能解决敌人看不到/子弹击杀不可见 | 仅作为未来战术目标需求 |

## 5. 可调参数与初值（不是已测试过的最优值）

| 参数 | 建议实验初值 | 验证目的 |
|---|---|---|
| 手机普通战斗 zoom | 0.75 | 横向可见半径 225 → 300 |
| Boss 短时预览 zoom | 0.70 | 先看清 Boss/威胁方向，完成后平滑恢复 |
| 可见索敌安全边距 | 24 屏幕像素 | 敌人不是刚露一像素就被秒杀 |
| 曾在屏内目标的锁定宽限 | 0.25 秒 | 避免镜头边缘来回跳目标 |
| 敌群入场警告 | 0.8 秒 | 有“虫潮即将扑来”的感受 |
| 最短普通敌人可辨运动窗口 | 0.5 秒（仅体验目标） | 能观察到虫子跑近并被射杀 |
| 普通远程武器屏外开火 | 默认不允许 | 杀敌反馈留在画面 |
| 英雄级远距武器屏外开火 | 允许，但必须给边缘反馈 | 保留英雄/狙击身份 |

设计参数在独立实验场景中比较，不应无验证地成为所有战区的硬编码全局值。

## 6. 不破坏肉鸽 Build 的特殊规则

- **射程强化仍生效**：最大射程计算照常，屏内可见门槛只限定默认自动索敌“是否开始这次攻击”，而不是修改弹丸实际飞行范围。
- **远程 Build 保留强项**：狙击/轨道炮/英雄弱点锁定可在屏外发动有限次数远距攻击，但需可读提示；不作为所有普通枪械的默认能力。
- **范围传播保留强项**：火焰/毒素/电弧/爆炸的传播可以跨入屏外，不需要硬截断模拟；离屏结果通过边缘标记与入场压力体现。
- **进化后不能变成“屏外全自动清场”**：如一场战斗大部分击杀发生在镜头外，优先调整锁定/出场/视野，不直接砍进化伤害。
- **英雄被动的目标策略**与普通武器策略分离：凯恩专属狙击、薇拉猎杀蜂群等可以有特定远端目标；零的近身刀阵应优先给玩家看到敌人靠近。
- **站桩/移动**都不需要手动移动镜头；如以后使用视野朝向偏移（look-ahead），控制在小幅度、平滑，并允许玩家反向移动时迅速回到中心附近。

## 7. 分期实施建议

### M5.3a：镜头与战斗视野调参
- 在独立验证分支增加可配置战斗 zoom，实验 0.72/0.75/0.78。
- 局内宽屏/竖屏用同一“实际可见 world rect”查询；HUD 不参与缩放。
- 对比缩放前后的虫子入屏数量、机甲识别、预警可读性。
- 不改变火力、XP、掉落和敌人属性，单独验证镜头改善程度。

### M5.3b：可见索敌规则
- 普通武器优先可见区域内敌人并对边缘留缓冲；对已锁目标设短暂宽限。
- 拆分远程特种、英雄专属、连锁与范围传播的离屏例外政策。
- 测试屏内、屏外、边界抖动、世界边缘、相机视口改变及 Boss 目标。
- 输出“什么情况下仍然允许屏外死亡”规则说明，避免误把强力 Build 限死。

### M5.3c：入场与威胁提示
- 普通虫群从屏缘警告后出现；精英/Boss 使用更强预警。
- 镜头缩放期间刷怪点始终可达且不会贴脸；画面上下与左右都符合预期。
- 验证有足够可见虫潮密度和击杀反馈；不为“视觉停留”新增不公平无敌敌人。

## 9. 产品验收方法

对比三个配置：当前线上镜头（zoom 1.0）、纯 zoom 0.75、组合方案（zoom 0.75 + 可见索敌 + 入场预告）。同一测试条件记录：

- 左右方向可见的敌人数量与敌人首次出现位置；
- **屏外击杀占比**（攻击命中/死亡时目标是否在相机可见区域；区分特种远距武器合法例外）；
- 大批虫子出现时从“看见虫子”到“被清掉”的可观察过程；
- 玩家是否能明确感到“虫潮从四面涌入”；
- 机甲人形特征、Boss 预警和移动路线是否更容易辨认。

**建议的方向性目标（非实测）**：普通步枪等基础武器对**从未进入过可见区的虫子**发生的离屏击杀比例接近 0%；强力远距英雄武器允许清楚标示的例外。其它指标由首轮实际对比再冻结。

## 10. 与后续英雄/战区系统关系

- 六英雄和十二普通武器规划都应先遵循**可见性策略**：普通枪械默认攻击可见目标，英雄远距武器通过明确许可例外；近战/召唤有独立反馈。
- 三幕长局更需要看得见敌群密度和危险变化；M5.3 优先于 M6.0 制作大规模场景。
- 战区环境目标、Boss、精英和资源孵化巢的入场/视野提示复用本阶段接口，不另写不兼容的一套相机系统。
- 本 PRD 不因为用户不要求手机 FPS 优化就放弃输入和运行正确性；但**不会把 FPS 当作当前产品验收的优先维度**。
