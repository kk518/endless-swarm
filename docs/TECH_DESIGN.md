# 《无尽虫潮》技术设计文档（TDD）

> 文档版本：v0.1 · 状态：实现前设计基线 · 更新日期：2026-11-11  
> 关联文档：[产品需求文档](./PRD.md)  
> 项目仓库：kk518/endless-swarm  
> 首阶段交付：M0「可移动、能开火」；本文件同时规划 M1「五波闭环」的扩展接口。

## 1. 技术目标与边界

### 1.1 目标
为一款**手机竖屏、单指控制、俯视角自动射击**游戏提供低成本、可测试、可扩展的技术基线。

**M0 交付的最小闭环：**
1. 打开手机网页 → 点击开始 → 出现角色和虫群。
2. 用单根手指拖动浮动摇杆向任意方向移动；停止移动时角色仍自动射击。
3. 静止 0.8 秒触发动力装甲「火力展开」；再次移动立即退出。
4. 虫族追击并受击、死亡；玩家接触虫族会受伤，生命归零显示失败。
5. 能重新开始；可在手机浏览器运行，不强制依赖后端。

**M1 扩展：**四种武器、四种普通虫/一个 Boss、五波、波后免费三选一卡牌、通关与失败结算。

### 1.2 非目标
M0 不实现抽卡、完整波次、Boss、账号、排行榜、联网、广告、付费、复杂 ECS、多人同步、后端服务。不要为了假想的 10 万个实体引入复杂架构；首先保证手机上 100～150 只虫时可玩。

### 1.3 成功标准
- 移动/停止/展开/取消符合 PRD，且无需要点击攻击按钮的情形。
- 玩家可在 iOS Safari 和 Android Chrome 的近期版本中使用单指完成核心操作。
- 首屏能加载并进入游戏；切到后台再回来不出现大幅时间跳跃或死亡。
- 战斗逻辑通过自动化测试；打包能作为静态站点部署。
- 中端手机目标 60 FPS，密集战斗最低基线 30 FPS；真实设备测量，不用桌面 FPS 冒充真机表现。

## 2. 技术选型与架构决策

| 技术/方案 | 选择 | 原因 |
| --- | --- | --- |
| 游戏框架 | Phaser 3 | 2D 渲染、输入、摄像机和资源管理成熟，适合 H5 小游戏 |
| 语言 | TypeScript（strict） | 数据模型清晰，避免玩法扩展时逻辑失控 |
| 开发与打包 | Vite | 快速启动、静态构建、支持相对资源路径 |
| 渲染 | Phaser AUTO（优先 WebGL，支持回退） | 普通移动设备可用；具体表现需真机检查 |
| 碰撞 | 圆形/点距离检测 + 空间哈希 | 虫群数量较高时避免逐对全量检测 |
| 运行时状态 | 自管理小型 world + 纯 TypeScript 规则模块 | 比在 M0 引入完整 ECS 更简单，方便单测 |
| 单元测试 | Vitest | 无需浏览器即可测试移动、姿态、目标选择、伤害等规则 |
| 持续集成 | GitHub Actions（M0 可加入） | 验证 typecheck、test、build |
| 数据存储 | localStorage（仅设置与最佳成绩） | 无账户与后端依赖 |

**关键原则：** Phaser 负责渲染与输入适配；主要玩法规则以无 Phaser 依赖的 TypeScript 模块实现。不要让每只虫的行为分散到 Phaser Sprite 子类里。

## 3. 模块设计与依赖方向

### 3.1 分层

**UI / Scene 层**
- BootScene：创建公共纹理、初始化资源/设置。
- MenuScene：开始入口及极简操作说明。
- BattleScene：场景编排、渲染对象与 world 的映射、音画反馈。
- RewardScene（M1）：波后暂停、三选一卡牌。
- ResultScene：胜败展示、一键重开。

**输入与适配层**
- VirtualJoystick：单指触摸状态、方向向量、死区、取消触控。
- InputAdapter：触控与桌面键盘（开发调试）的统一 MoveIntent 接口。
- Viewport：安全区、缩放、横竖屏变化、UI 布局。

**玩法域层（不依赖 Phaser）**
- WorldState：玩家、敌人、投射物、计时器、当前阶段。
- GameLoop：固定时间步推进、暂停/恢复。
- MovementSystem：玩家/敌人移动及地图边界约束。
- StanceSystem：机动、蓄力、火力展开状态机。
- TargetingSystem：距离筛选与目标锁定。
- WeaponSystem：攻击冷却、射击、武器配置和效果。
- SpawnSystem：敌人预算、波次/时间驱动的出怪。
- CollisionSystem：近邻查询、接触伤害、投射物命中。
- DamageSystem：护甲/减伤（后续）、无敌帧、死亡事件。
- WaveSystem（M1）：每波计时、收尾、奖励过渡与终局。
- CardSystem（M1）：候选池过滤、三选一、属性修改。

**表现层**
- EntityViewPool：Sprite/粒子可复用池。
- EffectPresenter：受击闪烁、命中特效、短暂击退、枪口火光。
- HudPresenter：血量、火力展开进度、波次、倒计时。

**单向依赖：** Scene/UI → 输入适配与游戏域 → 纯数据；域模块不能依赖 Scene/Sprite。表现通过游戏事件或状态快照读取，不修改玩法属性。

### 3.2 推荐目录结构

- **public/** — 静态资源（后续美术与音频）
- **src/main.ts** — 初始化 Phaser Game 与页面事件
- **src/game/config.ts** — 游戏配置、设计分辨率、性能开关
- **src/game/scenes/** — BootScene、MenuScene、BattleScene、ResultScene（M1 加 RewardScene）
- **src/game/input/** — VirtualJoystick、InputAdapter
- **src/game/core/** — GameLoop、WorldState、types、events、math
- **src/game/systems/** — Stance、Movement、Targeting、Weapon、Spawn、Collision、Damage（M1 加 Wave、Card）
- **src/game/data/** — weaponDefs、enemyDefs、waveDefs、cardDefs
- **src/game/render/** — EntityViewPool、Effects、HUD、Viewport
- **src/game/utils/** — spatialHash、seededRng
- **src/styles/** — 游戏容器、触控区域和安全区
- **tests/** — 领域逻辑单测及流程测试
- **docs/PRD.md** — 产品设计
- **docs/TECH_DESIGN.md** — 本文档
- **.github/workflows/** — 类型检查、测试、构建流水线

M0 允许少量模块合并实现，但应保留清晰的领域边界；不要为了目录完整性提前写空模块。

## 4. 画布、坐标与手机适配

### 4.1 坐标系统
- **世界坐标**：所有角色、敌人、武器射程和移动速度使用游戏逻辑单位，单位为 world units/s，与设备像素密度无关。
- **屏幕坐标**：触控位置、摇杆半径、UI 布局使用 CSS/视口坐标。
- **世界摄像机**：以玩家为中心（或限制在地图边界），让玩家长时间保持屏幕中部附近；HUD 固定在屏幕空间。
- **基准可视布局**：按约 360 × 640 CSS px 设计竖屏界面；使用缩放和安全区域适配多比例全面屏，不强制裁掉关键 UI。

初版可采用固定尺寸竞技场、摄像机跟随玩家。屏幕变宽/变高时相应显示更多世界区域，但射程、速度和碰撞半径不变。

### 4.2 虚拟摇杆输入
- 仅在**战斗中屏幕下方操作区**启动摇杆，单手可触及；玩家点击「开始/卡牌」的触摸不应透传到战斗。
- 记录一个活动 Pointer ID；按下坐标为摇杆原点，拖动向量经过死区与最大半径钳制后得到长度 ≤1 的方向向量。
- 建议初值：触控死区 8 CSS px、有效最大拖动半径约 52 CSS px；均为可调参数。
- 松手、pointercancel、浏览器失焦时，**立刻清空移动向量**；避免「松手继续跑」。
- 不因为指尖小抖动反复进入/退出展开，使用移动输入阈值（例：归一化强度 ≥0.12 视为有效移动）和稳定判定。
- 游戏容器使用 touch-action: none，并防止页面滚动/选中文字；UI 区域仍允许正常点选。
- 桌面开发调试允许 WASD/方向键，同样映射为 MoveIntent，不影响手机单指设计。

### 4.3 生命周期
- 页面变为 hidden、失焦或 Phaser 失去运行焦点时暂停世界计时、攻击计时与生成计时。
- 返回页面后恢复固定步循环；不使用隐身期间的大 delta 追帧。
- 浏览器旋转、resize、地址栏出现/消失时重算画布与 HUD；保留玩家世界位置。

## 5. 主循环与状态机

### 5.1 固定逻辑步长
- 渲染按浏览器帧刷新；游戏逻辑使用固定步长 **1/60 s**，时间单位统一为秒。
- 累积渲染 delta，每帧最多执行 **5 次**逻辑更新；恢复前台时将异常大 delta 丢弃/截断，避免所谓“追帧”导致瞬间连发、涌怪或暴毙。
- 所有射速、位移、冷却、展开计时与无敌帧基于逻辑 delta，而非“经过多少渲染帧”。
- 场景仅负责调度和渲染同步，不在 Sprite.update 里藏独立玩法计时。

### 5.2 游戏阶段
M0：MENU → PLAYING → RESULT → MENU/PLAYING。

M1：MENU → PLAYING → WAVE_END → REWARD → PLAYING → RESULT。

- WAVE_END 先收束活动敌人与投射物，再冻结玩法并展示卡牌。
- REWARD 完全暂停世界时间，用户选卡期间不会受伤。
- 结算以后清理事件订阅、对象池活跃对象和输入指针，防止重开后残留。

### 5.3 事件
推荐事件集合：EnemySpawned、WeaponFired、ProjectileHit、EntityDamaged、EnemyKilled、PlayerDamaged、StanceChanged、WaveCleared、CardSelected、GameEnded。

事件用于表现与统计；**数值结算在领域系统内同步完成**。不要使用事件总线递归处理复杂伤害链，连锁爆炸需设置单步触发数量上限。

## 6. 关键玩法算法

### 6.1 玩家移动与姿态
- 移动向量归一化后乘速度和 dt，避免斜向移动更快。
- 使用手感优先的直接速度响应；不要加入明显移动惯性。初始建议玩家速度约 **185 world units/s**，需按角色碰撞半径和可视区域调整。
- **姿态判定看是否有有效移动输入**，而不是世界位移是否为零：角色顶墙时按住移动键不能白嫖展开增益。
- 机动：任何有效移动输入下持续正常开火。
- 蓄力：从无有效移动输入开始累计连续静止时间 0.8 秒；蓄力期间仍正常开火。
- 展开：连续静止 ≥0.8 秒，伤害倍率 ×1.35、**攻击频率**倍率 ×1.25（等价于攻击间隔除以 1.25）。
- 退出：出现有效移动输入的**同一个逻辑步**立即切回机动模式，不设撤架僵直或射击中断。
- 显示蓄力进度环、展开地面光圈；在 HUD 上突出两姿态的差异。
- 参数集中在配置表，自动化测试覆盖边界值 0.79/0.80 秒、频繁触碰摇杆、角色撞墙与暂停/恢复。

### 6.2 自动索敌
- 各武器按自己的射程查询候选目标，基础规则取距离最近且存活的敌人。
- 目标持续有效时保持锁定；新目标只有显著更近（建议距离降低 ≥15%）才抢占，避免来回抖动；超出射程/死亡立即换目标。
- M0 先实现简单最近距离选择（也可小规模遍历）；M1 接空间哈希按范围查询。
- 只有射程内有目标时自动开火；无目标保留/推进冷却，避免目标进入射程瞬间出现异常多发。
- 锁定的是敌人 ID 而非 Sprite 引用；销毁、重开或对象池复用后不得攻击旧对象。

### 6.3 射击与命中
- 武器定义包含：ID、基础伤害、攻击间隔、射程、弹速、弹数、散射角、穿透次数、效果标签。
- **电磁步枪**（M0）：按当前锁定目标角度发射弹丸；弹丸按物理时间直线移动、有最大存活时间和有效碰撞半径。
- 命中时立即扣血、生成受击事件，击杀进入死亡回收流程；投射物根据穿透预算决定回收。
- 同一投射物不能一帧内对同一敌人重复伤害；必要时保存本弹已命中敌人 ID。
- M0 不做玩家手动瞄准、手动换弹、复杂装弹时序。
- M1 新增的散射炮、电弧线圈、喷火器通过武器策略定义攻击行为；不在 BattleScene 写大量武器 if/else。

### 6.4 虫族 AI 与生成
- M0 工虫采用简化直接追逐玩家；速度和初始生命值配置化。
- 从玩家视野之外一定安全距离/世界边缘生成，不能贴脸生成。
- 敌人拥挤时使用轻量近邻分离或碰撞推开，避免大量虫子完全重叠；M0 可先做近邻间隔约束，M1 再优化。
- M0 可持续按预算生成工虫；M1 以每波独立配置决定时间、虫种、刷怪频率与同时存活上限。
- **不要使用全体虫子之间的 O(n²) 两两碰撞循环**。邻近查询由 SpatialHash（网格桶）完成，网格尺寸根据虫子直径调整。

### 6.5 接触伤害与死亡
- 玩家和虫子使用圆形碰撞体；根据距离平方判断接触。
- 初始建议玩家受击无敌帧 0.5 秒；无敌期间同源或不同敌人的接触伤害不重复扣血。
- 受击时有短暂颜色闪烁、轻微震动（可开关）和明显血量变更。
- 生命 ≤0 立即停止后续敌人生成/伤害结算，进入结果阶段。
- 敌人被击杀后只加统计、生成少量特效并回收到对象池；不要保留不可见活跃对象。

## 7. M1 波次、抽卡与成长的接口预留

### 7.1 波次控制
- WaveDefinition 包含：编号、持续秒数、敌种权重、刷怪节奏、最大存活预算、精英/Boss 事件。
- 第 1～4 波由倒计时结束；结束时清退剩余小怪（有可见退场效果）→ 展示免费三选一 → 开启下一波。
- 第 5 波以 Boss 击杀为通关条件，需超时兜底防止极端拖局。
- M0 只需定义可扩展的 GamePhase；无需提前实现全部波次逻辑。

### 7.2 卡牌数据模型
- 卡牌定义包含：ID、名称、稀有度（展示用途，可选）、权重、标签、前置条件、互斥条件、效果集合。
- 选择时：从当前合法卡池中通过可复现的伪随机数采样 **3 张互不重复**卡牌，玩家选择其中 1 张。
- M1 必须实现至少基础武器获取和数值/行为类效果；已满 4 槽时不提供无法生效的新武器卡。
- 为避免前期拿不到武器，前两次抽卡确保至少有一次新武器获得机会（实现方式需在 M1 单独测试）。
- 卡牌效果先应用到 run-level modifiers，再由各武器读取最终属性；避免直接修改底层武器定义原始对象。
- 游戏重开时重新生成 run state，卡牌效果不跨局保留。

### 7.3 可复现随机性
- 使用可注入 seed 的伪随机生成器，用于敌人生成与卡池抽取。
- 发生异常时能记录本局 seed、波次、主要卡牌/武器，并用相同 seed 复现关键场景（无需完整回放系统）。

## 8. 资源与渲染策略

### 8.1 M0 美术
- 优先通过一次性生成的几何纹理或本地占位素材表达：蓝色动力装甲玩家、深色甲壳虫、暖色弹道、展开光圈。
- **占位美术需要有辨识度和命中反馈**，但不在 M0 引入复杂动画制作成本。
- 所有素材使用原创或许可证明确允许的资源；不要复制已有 IP 的标志、角色形象或纹理。

### 8.2 性能预算
- 先以 **100～150 只活动虫族**做压力测试场景，数量上限可根据真机调整。
- Sprite、弹丸、受击粒子通过对象池复用；不要每次命中都创建大量新对象。
- 使用对象池 + 空间哈希控制碰撞与索敌成本；粒子数量、浮动伤害字数、屏幕震动频率设上限。
- Phaser 渲染对象采用统一图集或可复用纹理，避免每只虫都创建一次独立 Graphics 纹理。
- 禁止在每帧/每实体的高频路径内进行显著的临时数组创建、深拷贝、日志打印。
- FPS 统计与对象数量/碰撞查询次数作为开发调试 HUD，可在正式构建时关闭。

## 9. 配置、数值与数据定义

建议集中管理首版关键参数（以下仅为**初始测试值**）：

| 参数 | 初始建议 | 作用 |
| --- | --- | --- |
| fixedStep | 1/60 s | 领域逻辑步长 |
| maxCatchUpSteps | 5 | 每帧逻辑步数上限 |
| playerSpeed | 185 units/s | 玩家移动速度 |
| joystickDeadzone | 8 CSS px | 摇杆微抖过滤 |
| joystickRadius | 52 CSS px | 摇杆有效范围 |
| moveInputThreshold | 0.12 | 视为有效移动的输入强度 |
| deployTime | 0.8 s | 停步展开所需时间 |
| deployedDamageMultiplier | 1.35 | 展开模式伤害倍率 |
| deployedFireRateMultiplier | 1.25 | 展开模式射速倍率 |
| playerHitIFrames | 0.5 s | 受伤后的短暂无敌 |
| maxEnemiesTestBudget | 150 | 真机压力测试目标 |
| weaponSlots | 4 | 最多装备的武器数量 |

所有数值要从配置读入；不得把 UI 文本或固定帧数当成唯一真值。

## 10. 测试计划

### 10.1 自动化（Vitest）
- **移动**：单位向量归一化、斜向不增速、输入死区、松手归零。
- **姿态**：0.8 秒边界、移动即时退出、停止后重新计时、撞墙不错误展开。
- **索敌**：最近敌人、超出射程、目标死亡、锁定防抖。
- **攻击**：射速随倍率正确变化、无目标不开火、投射物有效期、重复命中限制。
- **碰撞**：接触伤害、无敌帧、死亡只结算一次。
- **生命周期**：暂停时所有逻辑计时不前进、恢复后不追大 delta。
- M1 增加：波次切换、抽卡唯一性与前置条件、四武器槽上限、卡牌重开清空。

### 10.2 集成测试
- 打开游戏 → 开始 → 单指移动 → 松手站桩 → 继续移动 → 受伤/击杀 → 失败 → 重开。
- 检查重开后无旧弹丸、旧敌人、旧监听器、旧状态残留。
- M1 检查五波流程中的暂停/恢复、选卡立即生效、死亡不能继续抽卡、Boss 通关。

### 10.3 真机验收清单
- iOS Safari 与 Android Chrome：首次加载、竖屏、手势操作、页面滚动拦截。
- 左/右手单指触控；地址栏高度变化、刘海/安全区、切后台/前台。
- 弹幕密集时不卡死，无严重误触；长时间按住摇杆不丢失控制。
- 至少测试一台中端 Android 和一台 iPhone，记录设备、浏览器版本、FPS、最大敌人数量。

## 11. 构建、CI 与部署

### 11.1 本地开发命令约定
- npm install / npm ci：安装依赖（提交 package-lock.json）。
- npm run dev：本地开发服务。
- npm run typecheck：TypeScript 静态检查。
- npm run test：运行 Vitest。
- npm run build：输出 dist/ 静态资源。
- npm run preview：本地验证生产打包。

具体 npm scripts 在初始化工程时落地，不能在尚未创建项目时声称已经可执行。

### 11.2 部署
- 构建产物为纯静态文件，可使用 Nginx 或静态托管。
- Vite 资源路径按相对部署路径配置，避免部署在子目录时 JS/CSS/图片 404。
- 本项目使用**独立访问路径与发布流程**，不覆盖旧游戏《老板正在靠近》。
- 代码仓库保持 Private；上线地址与服务器配置由用户确认后再实际部署。
- 初版没有服务端 API、密钥或数据库；不要把部署凭据提交到 GitHub。

### 11.3 Git 工作流
- main：可复现的基线；新功能优先用 feature/* 分支与 PR。
- PR 至少经过 typecheck + test + build；涉及移动/性能的功能需要真机截图或简短试玩记录。
- 每个 M0 系统独立小步提交，避免首次提交一个难以回滚的大型场景文件。

## 12. 实现顺序（M0）

**步骤 A — 工程骨架**
- Phaser/Vite/TypeScript strict、基本 Scene、画布缩放、CI、测试脚本。
- 可在手机浏览器加载蓝图场景，无控制台报错。

**步骤 B — 单指运动**
- FloatingJoystick → InputAdapter → MovementSystem → 角色 Sprite。
- 真机确认移动方向、死区、松手停止以及页面不跟随滚动。

**步骤 C — 敌人和射击**
- 一类工虫追击、生成/回收、基础电磁步枪自动寻找目标并持续开火。
- 命中、死亡、击杀统计能正确展示。

**步骤 D — 双姿态与伤害结算**
- 0.8 秒停步展开、火力倍率、展开特效、移动即时退出。
- 玩家受伤、短暂无敌、死亡结算与一键重开。

**步骤 E — 性能、回归、可玩入口**
- 100～150 虫压力测试、对象池与空间查询、真机输入和后台恢复检查。
- 提供可审阅的 PR 和可部署的构建产物；实际外网部署单独确认。

M0 完成后先试玩判断战斗手感，再进入 M1 的五波、武器、Boss、卡牌。

## 13. ADR：本阶段明确不采用的方案

1. **不采用多人在线和服务端权威状态**：M0 单机无需后端，网络会增加延迟、调试与部署负担。
2. **不采用重量级 ECS 框架**：目前实体种类少，轻量世界状态和系统函数足够；未来确有瓶颈再重构。
3. **不使用每只虫单独 Phaser 物理体做全量相互碰撞**：更易出现密集群体性能问题；优先自定义圆碰撞与空间哈希。
4. **不在战斗中提供攻击按键**：和单指产品定位冲突。
5. **不提前做抽卡/养成/付费系统**：M0 只验证基本战斗是否有趣。

## 14. 风险与待验证事项

| 风险 | 处理方式 |
| --- | --- |
| 手机浏览器长按触控丢指针 | pointercancel / blur 清理、页面触控限制、双平台真机测试 |
| 站桩被虫海惩罚过强或不够强 | 展开倍数/延迟配置化，通过录像与试玩观察调整 |
| 单指浮动摇杆遮挡战斗 | 限制操作区域、适当透明度、移动角色放在画面中部 |
| 子弹与敌人过多导致掉帧 | 对象池、网格查询、降低装饰性粒子优先级、限制最大活跃数 |
| 锁敌频繁改变方向不自然 | 目标 ID 保留与 15% 切换阈值 |
| 切后台后逻辑跳跃 | 页面失焦暂停 + 固定步 delta 截断 |
| M0 开发过大 | 以一个武器、一种虫、双姿态、一局失败/重开作为严格验收点 |
