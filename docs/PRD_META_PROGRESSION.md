# 《无尽虫潮》局外成长系统 PRD：星际军械库

> 版本：PRD v1.0 · 规划阶段：**M7 局外成长（明确列入产品路线图，尚未开发）**  
> 日期：2026-11-11 · 优先级：**确定要做，具体数值在 M5.2 试玩后冻结**  
> 关联：[产品总纲 PRD v2](PRD_V2.md) · [M5.2–M8 路线图](ROADMAP_M6_M8.md) · [试玩计划](PLAYTEST_PLAN.md)  
> 目标：打造「每局都有收获—返回基地做研发—选择机甲配置—尝试新流派」的**永久成长闭环**。

## 1. 核心设计决定

### 1.1 玩家体验目标
即使玩家第五波前死亡，也能积累一点“战备数据”，返回战备基地解锁研究、机甲和出击方案。下次开局有新的目标，既感到**打得更久会更强**，又不会因此失去原有的**单手走位、武器进化、Boss 读招**玩法。

基本循环：

`出击 → 击杀/通过波次 → 结算战备数据 → 军械库研发/解锁 → 选择机甲与初始武装 → 再次出击`

**必须区分三层成长：**
1. **局内 XP**：仅在本局升级，重新开局清零；
2. **波后战术卡**：仅在本局构筑，重新开局清零；
3. **局外战备**：永久保存的货币、研发等级、出战配置和成就，重新开局保留。

### 1.2 纵向与横向成长并存（产品决策）
过去路线图更偏向只做横向解锁；本版调整为**小幅、有限的永久属性升级 + 更重要的横向解锁**，不再把永久战力完全排除在范围外。

- **纵向**：永久火力、射速、机动、装甲的少量成长，升级效果真实且有严格上限；
- **横向**：解锁不同机甲底盘、初始武器和挑战契约，带出战取舍与流派变化；
- **收集/成就**：解锁条件、挑战记录、战区档案，作为长期目标；
- **禁止无限叠数值**：研究树必须有限级且可满级，长期游玩不能无限提高伤害；
- **禁止付费影响难度**：首版没有付费货币、付费研发、广告复活或体力门槛。

### 1.3 不能破坏的产品定位
- 一根手指仍能完成移动与自动攻击；基地界面可单指点选，不增加战斗中的第二操作键。
- 目标单局仍是短局；研发与整备应只占 **10–30 秒的可选间隙**，不得强迫逐页点红点。
- 新手首局**直接出击**，基地可在结算后自然解锁；不强制首次进入研究树。
- 对应 Boss 技能仍要可躲，不能靠永久属性“免疫”错误走位。
- 每一局都应允许不消费战备数据直接重新开始；升级是动力而非义务。

## 2. 系统结构与优先级

| 子系统 | M7.0 | M7.1 | 设计价值 |
|---|---|---|---|
| 战备数据结算与持久化 | **P0** | 调参 | 失败也有进度 |
| 小型永久科技研发树 | **P0** | 扩展分支 | 看得见的长期升级 |
| 基地/研究界面 | **P0** | UI 优化 | 有明确回访入口 |
| 出击机甲底盘 | 默认底盘 + 2 种可解锁底盘（P0） | 第三/第四底盘（可选） | 机动/火力风格差异 |
| 初始武器配置 | 默认步枪；先支持 1 种替换（P1） | 逐步解锁其他初始武器 | 初局打法不再单一 |

## 3. 经济系统：战备数据

### 3.1 单货币设计
唯一可累积货币命名为 **「战备数据」**，由战斗表现获得。它既是研发材料也是机甲授权成本。M7.0 不设计第二种货币、宝箱随机抽奖或复杂资源兑换。

### 3.2 结算公式（**规划初值，必须平衡测试**）
```text
如果本局存活时间 < 20s 且没有完成任何波次：
    战备数据 = 0
否则：
    基础参与奖励 = 8
    波次奖励 = 6 × 实际完成波次数（0–5）
    击杀奖励 = min(16, 2 × floor(有效击杀数 / 25))
    通关奖励 = 胜利时额外 24
    当局战备 = 上述四项合计
```
- **胜利预计最高 78**；普通第二波失败（已通过 1 波、击杀约 50）约 18；
- 退出、主动重开、浏览器刷新不是完成结算，不可重复领；
- 奖励不因装备高级机甲而降低，也不因等级高增加刷钱倍率；
- 挑战契约未来可提供 **有限额外奖励（建议 +10%～25%，需后续测试）**，不能使普通模式沦为亏本玩法；
- 同一 run 的结算必须**幂等**：结束事件/重复点击/页面恢复都不可重复发货币。
- **需特别验证**：新手是否经常在 20 秒内阵亡，导致完全没有收获；如发生则调整基础门槛，不允许直接惩罚新手留存。

示例（计算规则核对）：

| 战绩 | 参与 | 已完成波次 | 有效击杀 | 胜利 | 奖励 |
|---|---:|---:|---:|---|---:|
| 首波阵亡，存活 28s | 8 | 0 | 20 | 否 | **8** |
| 通过一波后阵亡，50 击杀 | 8 | 6 | 50 | 否 | **18** |
| 通过三波后阵亡，120 击杀 | 8 | 18 | 120 | 否 | **34** |
| 五波全通，200 击杀 | 8 | 30 | 16 | 是 | **78** |
| 秒退/刷新 | 0 | 0 | 0 | 否 | **0** |

系统不得通过人为缩短对局制造高效率刷钱，且不要求玩家为了收集货币反复刷前两波。

### 3.3 进度与奖励节奏
- 首次完成 1–3 局，应有机会购买第一项基础科技；预计首级花费约 35–45 数据。
- 初期每 **2–4 局**应有一次可见的军械库目标变化（试玩目标，不是保证）；中后期逐渐放缓。
- 研究和机甲成本通过固定数据表配置，严禁隐藏实时变价和强制等待。
- 科技树可以最终毕业；毕业后的追求转向契约、构筑、战绩和外观，不新增无限属性槽。

## 4. 永久科技研发（M7.0 P0）

总共 **5 个研究项目、9 个可购买等级**。研究项目按军械、动力/防护、战术情报分组；各项效果直接来自存档，不与局内 XP 等级混淆。

| 分支 | 研发项目 | 等级上限 | 每级效果 | 购买费用（从 Lv.0 依次） | 满级效果 |
|---|---|---:|---|---|---|
| 军械 | **精密枪管** | 3 | 全武器基础伤害 +2% | 35 / 55 / 85 | +6% 伤害 |
| 军械 | **能量循环** | 2 | 全武器攻击频率 +2.5% | 45 / 80 | +5% 频率 |
| 动力 | **伺服强化** | 2 | 移动速度 +2% | 40 / 75 | +4% 速度 |
| 防护 | **复合装甲** | 1 | 最大装甲 +1 | 100 | +1 生命 |
| 情报 | **战术数据库** | 1 | 出战前可预览四条武器进化配方 | 45 | 配方信息解锁 |

> 备注：这里的“9 级”是 3+2+2+1+1；共 5 个项目，不应误读成 9 个不同项目。  
> 规划中的花费总计 **560** 战备数据（35+55+85+45+80+40+75+100+45=560），仍需按真实局长/胜率修订。

### 4.1 数值应用次序
`基础角色/武器属性 → 科技永久加成 → 选定机甲底盘修正 → 本局 XP 强化 → 本局波后卡 → 展开/超频/连杀临时效果`。

- 属性百分比以**乘算**为主，但科研部分独立明确限制，不因为其他强力卡循环增长；
- 研究上限固定；满级时不再允许购买，额外支付不会发生；
- 防护的 +1 最大生命只在开局应用；不得在一局中途因为刷新网页再次增加生命；
- 不因为局外科技等级更高改变武器进化配方、抽卡概率和敌人伤害规则；
- 调整基线难度时以**未研发的新玩家也可学习和通关**为原则；科技提供容错，不承担“不升就过不了第一局”的设计义务。

### 4.2 先后与购买规则
- 科技项目可以自由选择，**不要求完整前置链**；推荐初始展示军械/动力的低成本项目；
- 点击购买前显示消耗、当前等级、下一等级的真实效果与剩余货币；
- 货币不足时按钮禁用并给出差额，不出现负数或未生效但扣费；
- 购买成功后立即保存，下一局生效；**正在进行的当前一局不能在暂停时点科研卡偷加属性**；
- 未来版本如需洗点，独立设计，不在首版默认“花钱重置”；
- 已购买研究在当前存档中永久有效，不因本局失败而丢失。

## 5. 机甲底盘解锁与出战配置（M7.0 P0）

### 5.1 底盘不是越来越强的三个等级
三个底盘的初始配置如下（平衡初值）：

| 底盘 | 初始状态 | 强项 | 代价 | 解锁成本 |
|---|---|---|---|---|
| **标准型「哨兵」** | 默认解锁 | 所有属性基准、无惩罚 | 无 | 免费 |
| **机动型「游隼」** | 选择出击时应用 | 移动速度 +8%，适合远距离风筝 | 最大生命 −1 | 120 数据 |
| **重装型「壁垒」** | 选择出击时应用 | 最大生命 +1，适合短暂停步展开 | 移速 −6% | 120 数据 |

规则：
- 默认始终可以使用标准机甲，不允许锁定免费底盘；
- 底盘改动是**有代价的横向差异**，不是线性伤害碾压；
- 每局只能选一种底盘，不能叠加；
- 底盘和永久科技可以叠加，但最大生命最终至少为 1；
- 解锁后永久免费选用，不扣维护费、不抽随机部件；
- 新底盘使用统一人形机甲轮廓与军武美术规范，可以先通过颜色标识/挂架区分，不要求新增 3D 模型。

### 5.2 初始武器配置（M7.0 P1 / M7.1 扩展）
- 初期仍以**电磁步枪**为默认起始武器；后续解锁「散射炮起手」「电弧起手」「喷火起手」等可选初装；
- **开局只有一把初装武器**，等级仍从 Lv.1 开始，不绕过 4 个武器槽上限；
- 初装武器不属于局外永久武器等级，不会开局就赠送 Lv.5 或终极进化；
- 允许用成就条件或战备数据解锁，具体解锁成本与条件在 M7.1 定标；
- 初装选择界面应明确攻速、射程、近战/远战定位与初始难度，不让“被动选错导致不可生存”。

## 6. 战绩、成就与长期目标（M7.0 P1 → M7.1）

### 6.1 首批建议挑战
1. 完成第一波；
2. 累计击杀 100 / 500 / 2000 只虫；
3. 首次通关；
4. 首次将任意武器进化；
5. 用不同进化形态通关；
6. 单局无伤通过指定波次。

M7.0 可以仅展示进度、成就徽章；M7.1 再决定是否给予**一次性解锁**或少量战备奖励。成就不得无限重复领货币。

### 6.2 成就数据口径
- 「累计击杀」只在一次 run 最终结算时入库，不每帧频繁写存档；
- 「首次通关」只能从假变真，不能退回；
- 同一局重复发结算不能重复累计击杀、胜场或成就奖励；
- 历史旧版本若只有最高纪录，不能虚构累计击杀与完成次数；默认从引入版本开始统计，UI 给出说明。

### 6.3 挑战契约（M7.1 P0）
解锁几项显著但公平的规则修改，例如：
- **虫群狂潮**：普通刷怪密度增加；
- **轻装行动**：最多 2 个武器槽；
- **战备紧缩**：补给品生成间隔增加；
- **高压作战**：允许部分敌人更早出现。

完成契约可解锁徽章、记录或受控的额外战备数据；契约不应强制使用指定底盘，也不应制造无法闪避的随机死亡。

## 7. 产品界面与交互

### 7.1 入口
- 首次启动：`开始出击`作为最大最明显的按钮，不强制去基地；
- 失败/胜利结算：展示「本局战备 +N」「当前总额 M」，提供`立即再来`和`返回军械库`；
- 军械库首页三块：**科技研发 / 机甲整备 / 战绩档案**；
- 机甲整备：一个当前选中底盘、一把起始武器、预计属性变化和「开始出击」；
- 技术研究：紧凑列表、真实等级/费用、是否已满级，不做过度复杂的无限滚动科技树；
- 已满级研发项目以清晰的“MAX”展示，不出现可购买按钮；
- 不能使用基地界面代替三选一卡：局内和局外成长是不同空间。

### 7.2 操作约束
- 全流程可单指点选，支持窄屏纵向滚动和刘海屏安全区；
- 每次购买/切换最多两步：点项目→确认/即时生效；默认低风险购买可直接单击，必要时可撤销短窗口（需后续 UX 选择）；
- 返回出击在任意基地层级最多两次点击；
- 没有红点轰炸、签到弹窗、看广告按钮或长时间升级动画；
- 盲测应让玩家能区分“本局 Lv.”和“军械库科技等级”；
- 消费时应有无效操作反馈，但不能诱导大量误购。

## 8. 存档与数据正确性（P0）

### 8.1 数据模型（逻辑定义）
```ts
type MetaSaveV1 = {
  schemaVersion: 1;
  research: Record<'barrel' | 'cycle' | 'servo' | 'armor' | 'intel', number>;
  currencyBalance: number;        // 非负整数
  totalEarned: number;            // 非负累计总收入
  unlockedChassis: ('sentinel' | 'falcon' | 'bastion')[];
  selectedChassis: 'sentinel' | 'falcon' | 'bastion';
  unlockedStartingWeapons: ('rifle' | 'scatter' | 'arc' | 'flame')[];
  selectedStartingWeapon: 'rifle' | 'scatter' | 'arc' | 'flame';
  achievements: string[];
  lifetimeKills: number;
  completedRuns: number;
  victories: number;
  lastSettledRunId: string | null;
};
```

工程实现可采用更稳健的事务提交、存档快照及已结算 run ID 的有界去重集合，以上仅定义产品必需字段，不强迫使用这段 TypeScript 作为最终存储结构。

### 8.2 存档要求
- H5 初期使用带 `schemaVersion` 的本地存储；保存设置与成果分离，避免更新音量设置覆盖战备余额；
- 更新版本迁移保留原有本地最佳纪录和音量选项；
- 写入成功后才显示「购买成功」，防止浏览器禁用存储时误导玩家；
- 存储不可写、无痕模式、配额不足时需给出可见提示：**当前进度无法持久保存**；不偷偷假装成功；
- 无法从早期无持久记录的版本还原历史局数/货币，不追溯发放“补偿财富”；
- 不跨浏览器同步，没有账号和云存档；需明确提示玩家清理浏览器缓存会丢失进度；
- 重复结算、重复按钮点击及刷新恢复不能重复发货币；货币余额绝不能负数或非有限值；
- 出击过程中对当前应用的局外研究和底盘配置使用**不可变快照**，不能读写存档改变当前战斗；
- 不在后台持续产生货币，不设计挂机收益或每日体力重置。

### 8.3 多标签页冲突
浏览器同时打开两个游戏页可能导致存档“后写覆盖先写”。M7.0 至少：
- 检测存档版本/更新时间，发现冲突时阻止当前页继续购买并提示刷新；
- 不在冲突状态下自动合并货币或双倍入账；
- 计划 M7.1 再评估跨标签页同步与手动导出/导入。

## 9. 平衡与反通胀

- **永久增强硬上限**：科技伤害 +6%、射速 +5%、移速 +4%、装甲 +1；不能无限购买提高。
- **新手可通关**：必须能在没有永久研究情况下通过合理走位和构筑击败 Boss；不把难度围绕满级科技调校。
- **两套实验都要测**：零科技新角色 vs 科技满级；比较前两波存活、进化达成、Boss 可躲性与胜率差异。
- **不能因为玩家变强就对所有敌人无提示提升血量**；挑战难度应由公开契约、敌人波次变化决定。
- **后期毕业有终点**：研究和机甲解锁后，以挑战、勋章、可选外观维持长线动力，不能靠无限数值任务绑住玩家。

经济验证建议使用至少三类模拟玩家：首波经常失败的新手、偶尔过三波的中级玩家、稳定通关的熟练玩家。记录达到第一项研发、第一副底盘、基础研发毕业的预估局数；如果新手需要几十局才能首次研发，降低前期费用而不是引入广告或买数据。

## 10. 系统验收标准（AC）

| ID | 验收描述 |

## 11. 开发分包与风险

| 版本 | 最小切片 | 依赖 | 明确非目标 |
|---|---|---|---|
| **M7.0a** | 结算公式、版本化本地存档、重复结算保护、UI 战备数 | M5.2 的局长/击杀基线 | 科技树/底盘均不做 |
| **M7.0b** | 科技研发 UI、扣费、实际属性应用、上下限测试 | M7.0a 存档稳定 | 无限科技、洗点、云档 |
| **M7.0c** | 三种底盘选择、解锁、出战前配置与完整回归 | M7.0b | 新场景/新武器类型 |
| **M7.1** | 起手武器选择、契约、成就、存档救援 | M7.0 数据与使用情况 | 社交、排行榜、广告、复杂经济 |

**核心风险与缓解：**
1. “失败仍成长”变成“刷钱上头” → 按波次与有效时长奖励、每局上限、短局奖励反套利；
2. 永久数值破坏 Boss 公平 → 明确低上限、无科技可通关、难度不随科研暗增；
3. 研发界面比战斗更费操作 → 基地可跳过、研究项不多、两次点击内回战斗；
4. 刷新导致存档丢失/重复领币 → 版本化存档与幂等结算、可见失败提示；
5. 多标签页覆盖进度 → 检测冲突，优先保护余额与已解锁成就；
6. 研发进度太慢导致挫败 → 数值和成本需要在至少三类熟练度样本上验证。

## 12. Go / No-Go

- **进入开发条件**：M5.2 完成试玩，证明基础移动、自动攻击和 XP 节奏可以成立；M6 若确认提高局内策略，也可与 M7.0a 的存档准备并行**设计**，但不能同时发两个未验证的新玩法。
- **M7.0 上线条件**：经济能被人工复算；无双发币、无负余额/损档；新人一局内看到未来可购项目；科技实际生效且满级封顶；无科技仍能通关；Android/iPhone 的存档与重启体验可靠。
- **M7.1 继续条件**：玩家真实使用基地系统并愿意重复出击；若局外研发不能提高复玩兴趣，优先修战局本身，不增加复杂经济和更多科技层数。

---

**产品结论：永久成长会做，而且要真正让玩家从失败中积累成长；但必须是有限科技、机甲出战差异和长期目标的组合，而不是无限堆数值。**
