## 1. 一句话产品定义

《无尽虫潮》是一款面向移动端单手玩家的**科幻机甲虫潮生存 Roguelite**：玩家只控制走位，四套武器独立自动索敌射击；**停下展开高火力阵地，移动则靠机动性在虫海中寻找生路**。击杀获得 XP 升级、波间选择战术模块，将普通机甲逐渐搭建为多武器进化形态，并在持续变化的虫巢战场中突破封锁。

产品标识：**“只动一根手指，作出真正的战术选择。”**

### 1.1 核心设计支柱（由高到低）

| 支柱 | 玩家能感受到什么 | 对应硬约束 |
|---|---|---|
| **机动 vs 展开** | 越是危险越想停住输出，但必须判断何时撤离 | 永远保留站桩增强 + 移动自动射击；零额外射击键 |
| **虫潮压迫与脱困** | 危机来自包围、远程牵制和可预见的技能，而非随机暴毙 | 攻击前摇可读、有躲避空间；拒绝直接贴脸刷怪 |
| **构筑带来行为变化** | 解锁新挂载与进化后，清怪方式发生可见改变 | 不把“+5% 全伤害”当作主要新增内容；选择必有真实战斗效果 |
| **单手、短局、快重开** | 无说明也能上手；死亡后立刻知道原因并想换流派 | 无手动瞄准/换弹/技能轮盘；短屏触控优先 |
| **原创且统一的科幻审美** | 人类是工业冷硬，虫巢是变异有机，战士是人形机甲而非坦克 | 维持 M4 美术规范和 M4.1 瘦长机体、多挂载辨识度 |

优先级冲突时，宁可删除一个特效、武器或事件，也不能牺牲上述前四项。

### 1.2 不是要做什么

不做完整 3D 多人射击、手动准星射击、复杂 MMO 角色养成、不靠广告复活来修复难度、不以堆武器数量代替设计，也不依赖无限永久数值掩盖局内构筑的问题。**M7 已明确规划有限永久科技研发及机甲解锁**，但在玩法验证前不引入帐号、服务端强依赖、签到和复杂多货币经济。

## 2. 用户与使用场景（待验证的产品假设）

### 2.1 核心人群
- **轻量幸存者玩家**：短时游玩，喜欢自动攻击和满屏清怪，希望操作门槛低。
- **构筑玩家**：研究卡牌配方、进化时机，追求复玩差异。
- **碎片时间手机玩家**：单手、竖屏、无额外摇杆组合和精确射击手势。

### 2.2 玩家任务（JTBD）
- “我有几分钟，想快速开一局，不想复杂操作。”
- “我想靠走位和卡牌组合在越来越密的虫潮里反败为胜。”
- “这局我走雷暴控制流，下局想试霰弹近战流，而不是按同一套路堆伤害。”

### 2.3 情绪曲线
1. **0–15 秒：**理解移动、自动攻击、松手展开；
2. **第 1 波：**建立击杀/经验正反馈，体验第一轮升级；
3. **第 2–3 波：**解锁第二武器，第一次形成有代价的站桩/移动选择；
4. **第 3–4 波：**虫巢战区施压，玩家明确判断“先拆威胁还是先突围”；构筑趋于成形；
5. **第 5 波：**Boss 考验机动、目标优先级和核心构筑；
6. **结算：**能说清失败原因、看到本局强项，主动尝试另一流派。

这是**目标体验曲线**，不是当前所有步骤均已实现的声明。

## 3. 当前已实现的产品基线（M5.1）

| 系统 | 已存在的能力 | 此后最可能的缺口 |
|---|---|---|
| 操作 | 手机单指浮动摇杆，自动索敌射击，停止约 0.8 秒展开 | 手势容错、右/左手舒适度、遮挡与真实机型测试 |
| 战斗 | 机甲、人类 vs 虫巢；波次、群刷、自爆虫、精英掉落、Boss | 战场目标和敌方战术决策不足；后期压力需要实测 |
| 构筑 | 22 张波末卡、四武器、击杀 XP、Lv.1–25、每武器 Lv.1–5 | 高级配方的实际达成率未知；多次暂停可能割裂 |
| 进化 | 轨道歼灭炮、毁灭者霰弹炮、雷暴矩阵、炼狱焚化器 | 流派差异/数值强度还未被真机试玩量化 |
| 场景 | 单张战区，工业军武 × 暗黑有机虫族的 2.5D 视觉 | 战场空间尚缺目标点及叙事节奏 |
| 发布 | 私有 GitHub 仓库、验证分支 CI、静态站点部署与版本核对 | 缺一套正式的人工试玩、表现和发布闸门 |

**不得将“自动单测通过”写成“真机性能、爽感、复玩率已通过”。** 目前后面这些指标的真实基线均为 **未知**。

## 4. 核心循环与产品边界

### 4.1 局内主循环
- 进入战场 → 单手移动/自动火力 → 击杀得 XP → 局内三选一小成长 → 继续生存；
- 通过第 1–4 波 → 波后战术三选一（大幅强化/新武器/进化前置）→ 下一波；
- 在第 5 波突破 Boss → 胜利/死亡/超时结算 → 查看构筑与选择再来一局。
- **M7 计划新增局外循环**：结算获得有限战备数据 → 在军械库购买永久科技/解锁机甲底盘 → 选择出战配置 → 开启新一局。局外进度与局内 XP、战术卡分别计数，不能混同。
- M6 开始增加一层**可选的短时战场目标**，目标必须与生存和走位发生冲突，但不能强制额外操作按钮。

### 4.2 关键时长与节奏约束
- **当前已实现战斗计时上限**：第 1–5 波分别为 35/40/45/50/90 秒（总计 260 秒；最终波可能提前通关）。
- **目标总单局**：约 4–6 分钟战斗 + 选择/阅读时间（总局长需要真实记录；不声称稳定固定在此区间）。
- 经验升级建议目标：每 20–40 秒一次有意义的成长机会，但**不能通过过多暂停推高总局长**。
- 每 30–60 秒应产生至少一次可被玩家复述的**战术变化**：新敌人、目标出现、进化、波次压力变化，不能只有数值上涨。
- 波次 5 前需要至少一个可理解的“为 Boss 预留/抢占位置”的决策点；不可用无限刷怪替代关卡设计。

### 4.3 单手交互铁律
- 玩家只需一根手指移动，武器自动攻击；可用单击选卡，不能要求同时拖拽 + 点击。
- 未来战场目标通过走近、自动攻击、自动交互实现；拒绝投掷物主动瞄准/点击摧毁地图物。
- 失败原因必须可归因，特殊攻击有明显且足够早的预警。
- 带有重要信息的元素不可仅以颜色区分（形体、标识、动画、提示至少其二）。
- 9:16 及更高的全面屏都能阅读 HUD 与卡面；优先验证低端小屏布局。

## 5. 战斗设计原则：难不是血厚和敌人多

把难度拆成可观察的四个维度：

| 维度 | 玩家决策 | 设计手段 | 不允许的替代方案 |
|---|---|---|---|
| 空间压力 | 往哪里移动、在哪一角展开 | 追击虫 + 跃袭虫 + 环境目标位置 | 出生点直接贴脸，无法闪避 |
| 时间压力 | 先清怪还是先拆虫巢目标 | 可选的限时风险/增益，明显计时条 | 超短倒计时逼迫失败 |
| 构筑压力 | XP 优先升武器还是补生存 | 明确的进化配方、真实机制差异 | 隐藏配方、无效卡、随机错失 |
| 操作节奏 | 何时站桩获得火力，何时撤离 | 可预警的远程牵制与 Boss 技能 | 站桩无成本或站桩必死 |

新敌人、事件和 Boss 技能都必须表述清楚**创造了什么新决策**，否则不进入优先开发。

## 6. 成长与构筑的目标结构

### 6.1 双层奖励的分工
- **XP 战斗升级：**高频但轻量，武器 Lv.1–5 和基础火力/生存数值；
- **波末战术模块：**低频但强力，提供新武器、进化配方或构筑核心；
- **进化：**满足 Lv.5 + 战术材料，消耗一次 XP 升级；改变真实攻击机制。

M5.1 已具备四条进化路线的代码规则。后续优先调节**出现机会与配方可达性**，而不是继续加第 5/6 把武器。

### 6.2 构筑设计边界
- 每局最多四把武器；不是任何流派都能满进化，取舍应真实存在。
- 不强制所有玩家每局拿四种武器；两武器高等级流派可以是可行策略。
- 四个建议的验证样本流派：轨道贯穿、近战霰弹、雷暴减速、灼烧持续输出。
- 至少准备一种**非纯伤害胜利原因**（走位、战场目标奖励、控制减速），但不削弱自动射击的爽感。
- 在量化不同流派的完成率、胜率及选择率前，不加新武器族系或永久数值树。

## 7. 后续战区规则设计（目标而非实现）

### 7.1 可摧毁虫巢作为战场决策
- 地图出现有生命值、有明显轮廓且能被自动火力攻击的虫巢结构；
- 虫巢不是额外的“血厚敌人”：它产生可预见的战术压力，例如强化某个方向的虫群刷怪；
- 摧毁它应立即降低某类威胁或提供可量化奖励；
- 必须始终允许“不去拆，先保命”的选择，避免把单手休闲玩法变成任务打卡。

### 7.2 事件与 Boss 行为
- 事件数量少但区别大，不要随机弹窗强迫选择；关键事件有明显预告。
- Boss 从“高生命 + 冲锋”演进为两阶段、两种可躲避技能及一个有意义的时间窗口。
- Boss 的技能形状、危险提示、出口方向在短屏上清晰；**避免镜头抖动掩盖危险区域**。

### 7.3 关卡随机性
- 优先做“同一地图上的空间目标位置、敌群组合、事件顺序”变化；不要一次性造多个大地图。
- 各次随机规则可通过种子复现，便于分析平衡；不以纯随机决定玩家是否必死。
- 视觉表现遵循 [M4 美术规范](ART_DIRECTION.md)：人类工业据点被暗红虫巢侵蚀，机甲保持人形比例。

## 8. 局外成长与可重玩性（明确纳入 M7 产品规划）

**决策更新（2026-11-11）：M7 正式包含局外成长系统，不再只规划横向解锁。** 开发顺序仍受 M5.2 试玩与 M6 战场体验验证约束；**规划确定 ≠ 功能已实现**。

### 8.1 永久资源与军械库循环

每局结算可获得「战备数据」，失败也能积累少量进度；返回基地在「科技研发 / 机甲整备 / 战绩档案」中消费或查看。之后选择底盘与初装，直接重新出击。新手第一局不被基地流程阻断，游戏不强制玩家每局消费资源。

### 8.2 有上限的永久科技研究

规划初版 5 项研究、合计 9 个可购买等级：基础伤害最多 +6%、射速最多 +5%、移动速度最多 +4%、最大装甲 +1，另外可解锁进化配方情报。每项都需要战备数据，费用与升级上限明示，完全不会无限叠加。所有属性在新一局开始时快照生效，不能影响进行中的战斗。

### 8.3 机甲整备与横向选择

默认「哨兵」免费；「游隼」更快但生命少一格；「壁垒」生命更多但移速降低。每局只可选择一种底盘，三者是**带明确代价的侧向差异**而非依次淘汰的装备等级。后续扩展可选初始武器、挑战契约、成就与战绩档案。

### 8.4 局外系统设计红线

- 无科技的新手仍应能靠操作和构筑通关；不能把 Boss 难度按满科技才能胜利设计。
- 不强制签到、每日体力、广告复活、付费购买货币或隐藏倒计时科研。
- 对战备结算、扣费和存档迁移设置幂等与回归测试，不能重复发放或清空玩家进度。
- H5 首版仅本地存档，明确提示清理浏览器数据会丢失进度；无帐号、无云同步的功能不可假装已具备。
- 研发、机甲与挑战的成本、数值和首轮可得性在试玩后冻结。

**完整的资源公式、科技表、机甲参数、UI、存档设计和验收标准详见 [局外成长详细 PRD](PRD_META_PROGRESSION.md)。**

## 9. 体验质量标准与数据口径

以下是**规划阶段建议阈值，不是已观测数据或达标声明**。

| 指标 | 初始假设/门槛 | 取数方式 | 若未达标 |
|---|---|---|---|
| 首次上手 | ≥8/10 试玩者能在 15s 内理解移动和自动射击 | 无说明实机观察 | 修引导、摇杆与场景可读性 |
| 第一波完成 | ≥8/10 新手能够结束第一波并知道如何选择升级 | 试玩观察 | 调早期强度与卡牌文案 |
| 自愿重开 | ≥6/10 试玩者结束后主动再开一局 | 同人连续试玩 | 先修爽感、失败反馈和成长 |
| 进化可达性 | 具经验的试玩者第 5 波前有现实概率完成至少一条路线 | 固定种子模拟 + 试玩 | 优先改配方与 XP 节奏 |
| 操作可归因 | ≥8/10 能指出一次具体的站桩/撤离决策 | 短访谈 | 重新设计敌方压力及 HUD |
| 预警清晰 | ≥8/10 能在首次遭遇后理解虫巢/Boss 预警和躲避方向 | 无提示观察 | 改预警，不先增加伤害 |
| 性能底线 | 常见中端机 ≥30FPS，目标 60FPS；触控不断续 | Android Chrome/iOS Safari 真机压力测试 | 先做降级、预算、对象复用 |

**样本量说明**：10 人左右是方向性可用性检查，不能称统计显著；正式留存、支付和增长指标必须有真实渠道、合规数据与更大样本后再建立。

### 9.1 可选的事件记录草案
不必立即上报服务器；可在开发版本先**本地只读记录**，记录游戏事件和随机种子，不记录个人信息。建议事件：
- run_start（设备档位、玩法版本）、wave_start、wave_end、run_end（失败原因、时长、波次）
- level_offer/level_pick（候选 ID、选中 ID、当前等级、等待次数）
- tactical_offer/tactical_pick（配方倾向、已装备武器）
- weapon_evolved（武器/波次）
- player_hurt（伤害来源/姿态）
- hive_spawn/hive_destroy/hive_expire（M6）
- performance_sample（fps 档位、敌人/弹丸对象数；非身份信息）

**隐私要求**：如未来添加远程分析必须先明确告知用户、控制采集与保存期限，并确认适用法律/平台要求；当前版本无需为规划先创建帐号或服务端。

## 10. 版本门槛（Go / No-Go）

下一次新增内容前必须取得一轮真实试玩记录，至少回答：
1. 为什么死亡：站桩过久、看不清预警、火力不够，还是难度不公平？
2. 四条进化路线哪条最容易/最难达成，玩家是否理解原因？
3. 玩家在第 3–4 波有没有主动的位置/目标选择，还是单纯绕圈？
4. 手持不同机型时 UI、操作、帧率的最差情况是什么？

若**主动重开/首波理解/中端机性能**没有达到试验阈值，先完成 M5.2 可玩性修复，不开始 M6.0 增加系统。

## 11. 路线图及边界

| 阶段 | 主题 | 决策价值 | 是否已实现 |
|---|---|---|---|

## 12. 决策记录与待定事项

| 决策 | 当前立场 | 重新讨论的触发条件 |
|---|---|---|
| 仍用 2.5D Phaser 而非立即切 3D | 保持；用户已明确认可机甲+虫巢方向，重点是辨识与打击感 | 现有表现无法清楚表达战区目标或性能证据支持换引擎 |
| XP 由击杀直接获得，无经验球 | 保持；减少操作与性能负担 | 试玩证明地图上的拾取选择显著增强乐趣 |
| 继续单指自动射击 | **核心不可改** | 只有明确产品重定位才调整 |
| 波次是否继续固定五波 | M6 初期保留，以便对比前后效果 | 数据显示局长/节奏必须重排 |
| 是否做局外永久属性 | **确定纳入 M7：有限永久研究 + 机甲底盘解锁**，研究上限防止数值膨胀 | 真实测试显示新手难度/长期复玩受负面影响则调整数值和节奏 |
| 是否加入广告/内购 | 暂不做 | 有明确发行策略、留存证据及玩家体验设计后单独评估 |
| 是否立刻新增地图/武器 | 暂不做 | M6 战场目标和四进化流派被验证仍缺内容多样性 |

---

**总结：局外成长已经写进正式规划，但仍先验证基础战斗、再实现可持续军械库，最后才评估发行与商业化。** 这三件事的验证顺序不可颠倒。
