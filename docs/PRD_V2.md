## 1. 一句话产品定义

《无尽虫潮》是一款以**每局随机新鲜、失败也能成长、强力协同 Build** 为三大支柱的单手机甲虫潮 Roguelite。玩家局外选择不同资源战区并整备机甲，在战场中一指移动、自动射击、停步展开，击杀 XP 自动小成长；幕间决定武器、组件、融合方向与风险路线，战后带回地区材料永久强化装备。完整通关局的**目标战斗时长为 15–20 分钟**，不是当前 260 秒的原型局长。

产品标识：**“单指横扫虫潮，凑出逆天 Build；每次失败都离下一次突破更近。”**

### 1.1 核心设计支柱（由高到低）

| 支柱 | 玩家能感受到什么 | 对应硬约束 |
|---|---|---|
| **机动 vs 展开** | 越是危险越想停住输出，但必须判断何时撤离 | 永远保留站桩增强 + 移动自动射击；零额外射击键 |
| **虫潮压迫与脱困** | 危机来自包围、远程牵制和可预见的技能，而非随机暴毙 | 攻击前摇可读、有躲避空间；拒绝直接贴脸刷怪 |
| **构筑带来行为变化** | 解锁新挂载与进化后，清怪方式发生可见改变 | 不把“+5% 全伤害”当作主要新增内容；选择必有真实战斗效果 |
| **每局新鲜** | 同一战区不同的事件、路线、精英和奖励 | 受控随机、种子可复现、风险与收益可读 |
| **失败也爽** | 失败带回资源，离下一件装备/机甲解锁更近 | 战备与地区素材幂等结算、明确下一步 |
| **Build 上头** | 装备、模组、武器融合产生机制质变 | 自动 XP 小成长；幕间亲自选择关键组件 |
| **连续战斗与单手操作** | 打怪时不被升级面板打断，保持火力展开/撤退决策 | 战斗 XP 模态弹窗 0 次；无手动射击或多键操作 |
| **原创且统一的科幻审美** | 人类是工业冷硬，虫巢是变异有机，战士是人形机甲而非坦克 | 维持 M4 美术规范和 M4.1 瘦长机体、多挂载辨识度 |

优先级冲突时，优先保证三大 Roguelite 支柱、单手操作及无打断战斗；可以削减特效、事件数量或次要系统。

### 1.2 不是要做什么

不做完整 3D 多人射击、手动准星射击、复杂 MMO 角色养成，不靠广告复活修复难度、不以堆武器数量代替协同设计、不设计无限永久属性。规划中有**三种地区素材 + 通用战备数据、有限装备工坊/科技、机甲底盘**，但不加入抽卡付费石、日常强制签到、体力或账号服务端依赖。

## 2. 用户与使用场景（待验证的产品假设）

### 2.1 核心人群
- **轻量幸存者玩家**：短时游玩，喜欢自动攻击和满屏清怪，希望操作门槛低。
- **构筑玩家**：研究卡牌配方、进化时机，追求复玩差异。
- **碎片时间手机玩家**：单手、竖屏、无额外摇杆组合和精确射击手势。

### 2.2 玩家任务（JTBD）
- “我有几分钟，想快速开一局，不想复杂操作。”
- “我想靠走位和卡牌组合在越来越密的虫潮里反败为胜。”
- “这局我走雷暴控制流，下局想试霰弹近战流，而不是按同一套路堆伤害。”

### 2.3 情绪曲线
1. **0–15 秒：**理解移动、自动攻击、松手展开；
2. **第 1 波：**建立击杀/经验正反馈，体验第一轮升级；
3. **第 2–3 波：**解锁第二武器，第一次形成有代价的站桩/移动选择；
4. **第 3–4 波：**虫巢战区施压，玩家明确判断“先拆威胁还是先突围”；构筑趋于成形；
5. **第 5 波：**Boss 考验机动、目标优先级和核心构筑；
6. **结算：**能说清失败原因、看到本局强项，主动尝试另一流派。

这是**目标体验曲线**，不是当前所有步骤均已实现的声明。

## 3. 当前已实现的产品基线（M5.1）

| 系统 | 已存在的能力 | 此后最可能的缺口 |
|---|---|---|
| 操作 | 手机单指浮动摇杆，自动索敌射击，停止约 0.8 秒展开 | 手势容错、右/左手舒适度、遮挡与真实机型测试 |
| 战斗 | 机甲、人类 vs 虫巢；波次、群刷、自爆虫、精英掉落、Boss | 战场目标和敌方战术决策不足；后期压力需要实测 |
| 构筑 | 22 张波末卡、四武器、击杀 XP、Lv.1–25、每武器 Lv.1–5 | 高级配方的实际达成率未知；多次暂停可能割裂 |
| 进化 | 轨道歼灭炮、毁灭者霰弹炮、雷暴矩阵、炼狱焚化器 | 流派差异/数值强度还未被真机试玩量化 |
| 场景 | 单张战区，工业军武 × 暗黑有机虫族的 2.5D 视觉 | 战场空间尚缺目标点及叙事节奏 |
| 发布 | 私有 GitHub 仓库、验证分支 CI、静态站点部署与版本核对 | 缺一套正式的人工试玩、表现和发布闸门 |

**不得将“自动单测通过”写成“真机性能、爽感、复玩率已通过”。** 目前后面这些指标的真实基线均为 **未知**。

## 4. 核心循环与产品边界

### 4.1 三重循环
- **长期：**选择想刷的战区 → 取得地区素材 → 回军械库强化武器框架/装甲/动力/能源 → 解锁底盘与挑战 → 换战区或换构筑再出击。
- **单局：**完整局规划三幕、九段遭遇、15–20 分钟战斗；随机敌群/事件/幕间路线；重大奖励约 6–10 次；精英和 Boss 验证构筑。
- **即时：**一指移动/停止展开 → 自动攻击 → 击杀获得 XP → **自动小升级不中断** → 持续战斗。

详见 [三大支柱与长局设计 PRD](PRD_ROGUELITE_CORE_LOOP.md)。

### 4.2 现状与目标区分
- 当前生产 M5.1：五波 35/40/45/50/90 秒，最多 **260 秒战斗**，XP 升级逐次弹窗，局外无资源工坊。
- M5.2 规划：XP 自动升级，重大决策仅在**波末/幕间**，不再因为击杀升级持续暂停。
- M6.0：长局三幕、分支/事件、**最低限度的战备失败结算与可购买永久强化**；M6.1 进一步扩两战区与地区素材。
- M7 规划：装备工坊深入、永久科技/机甲与挑战。本文件不把未来规划误标为已上线。

### 4.3 延长局长的必要保护
- 15–20 分钟不能单纯延长同一波/加怪血；需要遭遇节奏、变化与阶段性目标。
- 幕间/安全节点要自动保存本局快照、支持暂停与恢复，避免网页被关闭后丢掉长局进度；恢复后不能重复抽取奖励或结算。
- 危险预警可读，单手无射击键；从基地到战区、奖励、工坊都能单指操作。
- **手机 FPS 不再是当前规划的主要限制或阶段门槛**；但崩溃、卡死、触控失效与存档丢失仍必须处理。

## 5. 战斗设计原则：难不是血厚和敌人多

把难度拆成可观察的四个维度：

| 维度 | 玩家决策 | 设计手段 | 不允许的替代方案 |
|---|---|---|---|
| 空间压力 | 往哪里移动、在哪一角展开 | 追击虫 + 跃袭虫 + 环境目标位置 | 出生点直接贴脸，无法闪避 |
| 时间压力 | 先清怪还是先拆虫巢目标 | 可选的限时风险/增益，明显计时条 | 超短倒计时逼迫失败 |
| 构筑压力 | XP 优先升武器还是补生存 | 明确的进化配方、真实机制差异 | 隐藏配方、无效卡、随机错失 |
| 操作节奏 | 何时站桩获得火力，何时撤离 | 可预警的远程牵制与 Boss 技能 | 站桩无成本或站桩必死 |

新敌人、事件和 Boss 技能都必须表述清楚**创造了什么新决策**，否则不进入优先开发。

## 6. 成长与构筑目标

### 6.1 关键设计：自动小升级，亲手选大的
- XP 升级：自动分配到战前/幕间设定的主武器与倾向；不中断战斗。
- 幕间卡/精英奖励：玩家亲自挑选武器、特殊模组、融合组件、分支风险与收益，**约 6–10 次有价值抉择**，而非 20 次纯数值点击。
- 现有四武器 Lv.5 单独进化保留；规划**跨武器联动**：雷霜封锁、炼狱引爆、磁轨风暴、壁垒熔炉等机制质变。
- 每局可有一个主融合流派和辅助协同；不强迫四武器满级满进化，允许不同流派有明显长处与短板。

### 6.2 局外资源和构筑不混淆
- 战区：钢铁遗迹/合金、感染巢穴/样本、雷暴前哨/晶体；通用战备数据可用于研究/解锁。
- 工坊：永久强化武器框架、装甲模块、动力推进器、能源核心；不直接赠送一局四把满级武器。
- 科技/机甲：小幅有限的通用成长与出战取舍；主流派仍需在局内构筑。
- 随机提供定向协同候选、转型候选和通用候选，既保留策略也避免纯运气卡死。

具体资源、强化和战区入口详见 [战区资源与装备 PRD](PRD_BATTLEFIELDS_EQUIPMENT.md)。

## 7. 后续战区规则设计（目标而非实现）

### 7.1 可摧毁虫巢作为战场决策
- 地图出现有生命值、有明显轮廓且能被自动火力攻击的虫巢结构；
- 虫巢不是额外的“血厚敌人”：它产生可预见的战术压力，例如强化某个方向的虫群刷怪；
- 摧毁它应立即降低某类威胁或提供可量化奖励；
- 必须始终允许“不去拆，先保命”的选择，避免把单手休闲玩法变成任务打卡。

### 7.2 事件与 Boss 行为
- 事件数量少但区别大，不要随机弹窗强迫选择；关键事件有明显预告。
- Boss 从“高生命 + 冲锋”演进为两阶段、两种可躲避技能及一个有意义的时间窗口。
- Boss 的技能形状、危险提示、出口方向在短屏上清晰；**避免镜头抖动掩盖危险区域**。

### 7.3 关卡随机性
- 优先做“同一地图上的空间目标位置、敌群组合、事件顺序”变化；不要一次性造多个大地图。
- 各次随机规则可通过种子复现，便于分析平衡；不以纯随机决定玩家是否必死。
- 视觉表现遵循 [M4 美术规范](ART_DIRECTION.md)：人类工业据点被暗红虫巢侵蚀，机甲保持人形比例。

## 8. 永久养成、多战场与重复游玩

**用户已确认：失败也要有成长，不同战场收集不同材料，材料用来永久升级装备。**

### 8.1 局外三步
1. 战区选择：看到哪个资源产地适合当前想升级的装备，去哪个战场刷；
2. 结算：无论成功失败都按有效战斗表现给予通用战备和对应主素材，合法领取只结算一次；
3. 军械库：升级真实装备模块、后续研究科技/解锁机甲；可以直接从缺料界面进入对应战区。

### 8.2 长线成长结构
- **装备工坊**：武器框架、装甲、推进器、能源核心；初版两件装备与两个战区同步推出。
- **科技研发**：少量全局可毕业研究，防止和工坊无限叠数值。
- **机甲底盘**：哨兵、游隼、壁垒具有移动/生命的明确取舍。
- **挑战契约与解锁**：长期深度来自新打法、新挑战，而不是无限 +%。
- 15–20 分钟长局需要**临时战斗快照与永久资源存档分离**，可靠恢复、失败结算和多标签页去重。

详细需求：[核心循环](PRD_ROGUELITE_CORE_LOOP.md) · [资源与工坊](PRD_BATTLEFIELDS_EQUIPMENT.md) · [局外研发与机甲](PRD_META_PROGRESSION.md)。

## 9. 体验质量标准与数据口径

以下是**规划阶段建议阈值，不是已观测数据或达标声明**。

| 指标 | 初始假设/门槛 | 取数方式 | 若未达标 |
|---|---|---|---|
| 首次上手 | ≥8/10 试玩者能在 15s 内理解移动和自动射击 | 无说明实机观察 | 修引导、摇杆与场景可读性 |
| 第一波完成 | ≥8/10 新手能够结束第一波并知道如何选择升级 | 试玩观察 | 调早期强度与卡牌文案 |
| 自愿重开 | ≥6/10 试玩者结束后主动再开一局 | 同人连续试玩 | 先修爽感、失败反馈和成长 |
| 进化可达性 | 具经验的试玩者第 5 波前有现实概率完成至少一条路线 | 固定种子模拟 + 试玩 | 优先改配方与 XP 节奏 |
| 操作可归因 | ≥8/10 能指出一次具体的站桩/撤离决策 | 短访谈 | 重新设计敌方压力及 HUD |
| 预警清晰 | ≥8/10 能在首次遭遇后理解虫巢/Boss 预警和躲避方向 | 无提示观察 | 改预警，不先增加伤害 |
| 长局可靠性 | 退出/恢复回到最近安全节点；存档/奖励不丢失、不重复 | Android/iPhone 浏览器中断与结算测试 | 先修快照、存档迁移、结算幂等 |

**样本量说明**：10 人左右是方向性可用性检查，不能称统计显著；正式留存、支付和增长指标必须有真实渠道、合规数据与更大样本后再建立。

### 9.1 可选的事件记录草案
不必立即上报服务器；可在开发版本先**本地只读记录**，记录游戏事件和随机种子，不记录个人信息。建议事件：
- run_start（设备档位、玩法版本）、wave_start、wave_end、run_end（失败原因、时长、波次）
- level_auto_applied（自动升级的武器/核心归属与等级）；旧版 level_offer/level_pick 留作 M5.1 历史对照
- tactical_offer/tactical_pick（配方倾向、已装备武器）
- weapon_evolved（武器/波次）
- player_hurt（伤害来源/姿态）
- hive_spawn/hive_destroy/hive_expire（M6）
- run_resume（恢复节点和存档版本）、resource_settled（资源构成与唯一结算标识）、gear_upgrade（装备等级及消费，均不包含身份信息）

**隐私要求**：如未来添加远程分析必须先明确告知用户、控制采集与保存期限，并确认适用法律/平台要求；当前版本无需为规划先创建帐号或服务端。

## 10. 体验验证与立项判断

已经确认的产品问题：
- 频繁 XP 升级弹窗破坏连续战斗：M5.2 必须消除。
- 现有 260 秒战斗局不足以承载更丰富的随机关卡与 Build：下一步规划三幕 15–20 分钟。
- 需要能刷地区资源和升级装备的局外目标。

进一步试玩验证的问题：
1. 自动小升级后玩家是否仍感到构筑可控？若没有，增加幕间重大选择，不恢复频繁弹窗。
2. 同战区连续三局的事件、路线、卡牌和组合是否足够不同？
3. 失败后能否立刻明确“差哪种材料、下一件要升级什么”？
4. 一个 15–20 分钟的完整局中，哪些时刻有质变、哪些时刻仍无聊？
5. 长局暂停/恢复、材料结算与触控是否可靠？

**不再以手机 FPS 指标作为 M6 立项闸门**。可玩性和进度正确性是优先级。

## 12. 最新产品决策记录（2026-11-11）

| 议题 | 当前决定 |
|---|---|
| 肉鸽三大支柱 | **每局新鲜、失败也爽、Build 上头** |
| 标准单局时长 | 从当前最多 260 秒原型，**目标 15–20 分钟完整战斗局** |
| 战斗升级弹窗 | **取消**，XP 自动小升级、幕间人工做重大选择 |
| 随机结构 | 战区主题 + 地图/目标/敌群/事件/奖励四层受控随机 |
| 构筑方向 | 四武器进化之外新增跨武器组合与模组标签 |
| 局外成长 | 分战区刷地区素材与战备数据 → 永久装备工坊/科技/机甲 |
| 运行安全 | 长局增加安全节点恢复、结算幂等、存档版本化 |
| 手机性能 | **本轮不把 FPS 作为设计优先级/立项门槛**，但不容许崩溃或触控失效 |
| 商业化 | 尚未确定，不做体力、签到、付费战力或强制广告 |

---

**总结：让玩家每局有意外、局内能亲手凑出强力组合、失败能带回永久收获；延长战斗时间的前提是丰富内容与可靠恢复，而不是简单拉长倒计时。**
