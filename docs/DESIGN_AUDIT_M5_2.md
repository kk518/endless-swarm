## 1. 本轮审查结论

目前技术闭环已存在：单指移动、自动射击、停止展开、波次、XP 升级、四武器等级/进化、波末战术卡及 Boss。下一步最值得验证的是**成长节奏、卡牌可理解度、选择打断成本、自动索敌的主观可控性、危险预警识别与低端机后期稳定性**。

**这份报告只给出设计风险及验证方法，不把可能问题写成已在玩家身上发生的事实。**

### 1.1 静态可确认的设计数值

### 1.2 XP 阶梯——数学核对，不是实测等级

按照现有公式 `xpToNext(level) = 8 + 3 × (level-1) + 2 × max(0, level-7)`，从 Lv.1 开始，达到以下等级需累计 XP：

| 达到等级 | 累计 XP | 必须兑现的升级选择数 |
|---:|---:|---:|
| 2 | 8 | 1 |
| 3 | 19 | 2 |
| 5 | 50 | 4 |
| 8 | 119 | 7 |
| 10 | 186 | 9 |
| 12 | 273 | 11 |
| 15 | 441 | 14 |
| 18 | 654 | 17 |
| 20 | 821 | 19 |
| 21 | 912 | 20 |
| 25（上限） | 1,326 | 24 |

**解释**：如果玩家在一局中达到 Lv.15，则理论上要至少进行 14 次战斗升级选择，外加至多 4 次波后战术选择。它可能让构筑更有趣，也可能令战斗频繁暂停；需要观察而不是预判好坏。

升级次数按达到等级计算，但如果死亡/胜利恰好发生在升级队列处理前，实际呈现次数需在全局状态流程中检验。

## 2. 优先验证的产品风险（不是已证实的 Bug）

| ID | 等级 | 事实依据 | 待验证风险与具体问题 | 验证方法 |
|---|---|---|---|---|
| **R01** | P0 | M5 使用逐次三选一，每次 XP 升级停战，溢出 XP 会排队 | 一局是否频繁中断？连续两次以上弹窗是否产生疲劳、误触？ | 记录每波弹窗次数、连续弹窗最大次数、玩家反应 |
| **R02** | P0 | 进化需武器 Lv.5 + 指定波后战术卡；波后卡只有四次选择 | 普通玩家能否在 Boss 前获得至少一条进化？是否知道为何未达成？ | 四流派真实局 + 实验记录每次配方候选和选择 |
| **R03** | P0 | `selectTarget` 优先最近敌人，上一目标在相近距离会被保留 | 未来新增虫巢建筑时，自动索敌可能与玩家意图冲突 | 先实测当前“我要打这个敌人”时的主观控制感，M6 再做靶场原型 |
| **R04** | P0 | 第 4/5 波敌人上限 86/95；多武器和持续灼烧共存 | 中端机后期掉帧、手机温升或丢触控风险 | Android Chrome、iPhone Safari 记录实际帧率/响应 |
| **R05** | P1 | 停止 0.8 秒展开，移动取消；后期攻击更密集 | 站桩是否仍可主动决策，还是移动永远更安全？ | 在第 2/3/4/5 波记录有价值的展开位置和撤离原因 |
| **R06** | P1 | 波次预警、自爆虫延时和首领攻击与大量多武器特效叠加 | 玩家是看懂危险后失败，还是根本看不清危险？ | 首次接触自爆虫和 Boss 时要求玩家复述危险形状与躲避方向 |
| **R07** | P1 | 波后卡可有“可靠加成 + 新武器 + 配方卡”三类；局内升级还有多种基础加成 | 玩家能否分辨“永久本局”“局外永久”（未来）与波末奖励的差异？ | 首波之后询问当前选项效果，不提前讲解 |
| **R08** | P1 | 随机使用 `Math.random` 及局内随机表，缺可复现单局种子 | 不同流派结果难以严格对照；平衡观察易被运气污染 | 先做人工日志，若确需严格 A/B 才计划引入测试种子 |
| **R09** | P1 | 目前只保留最高击杀纪录，结算不存详细单局战绩 | 无法验证 M7 战备收益、科研成本和不同熟练度负担 | M5.2 手工记录击杀/时间/波次，按模拟经济公式复算 |
| **R10** | P2 | HUD 有 XP、武器等级、Buff、波次和多武器特效 | 竖屏 9:16 小设备容易拥挤，升级卡可读性未知 | 至少 2 个手机屏幕尺寸截图和盲测 |

**等级定义**：表格中的 P0 是“规划验证优先级”，不是软件故障 P0；只有实测发生无法操作、不可恢复卡死、崩溃和重复发奖等才登记真实阻断 Bug。

## 3. 试玩执行任务（不得引导玩家的答案）

### 新玩家：首次接触（用户 A–D）
1. 发给玩家正式游戏地址，不解释界面按钮与武器规则，记录进入首局的秒数；
2. 观察是否能在 15 秒内自主移动、发现自动攻击、主动松手展开；
3. 第一次 XP 三选一出现时，只问“你会选哪张？”记录解释，不指导构筑；
4. 完成或失败第 1 波之后，询问“你觉得两个选卡界面有什么区别？”；
5. 在遭遇自爆虫或首领后询问“你认为攻击从哪里来，应该怎样躲？”；
6. 结算后先保持沉默、允许自由选择是否重开，再询问选择理由。

### 熟悉幸存者游戏的玩家（用户 E–F）
1. 自由玩一局，关注构筑目标和波次压力；
2. 局间访谈“你为什么升级这把武器？准备进化成什么？”；
3. 询问“哪里感觉主动作出决策、哪里只是被动绕圈？”；
4. 如玩家愿意，再尝试另一条明确不同的流派；
5. 区分卡牌太弱、难度太低和规则无法理解三种不同问题。

### 内部四流派平衡测试（非真人样本）
- 电磁步枪 → 轨道歼灭炮；
- 散射炮 → 毁灭者霰弹炮；
- 电弧线圈 → 雷暴矩阵；
- 喷火器 → 炼狱焚化器。

每条路线记录**最早达到 Lv.5 的时刻、是否拿到指定配方卡、是否在胜/负前完成进化**。若多次失败，需区分是“XP 少/卡牌候选没出现/选择上偏离/战斗提前失败”。本阶段没有内建固定种子流程，不能把不同随机局当成完全可比的实验。

## 4. 记录字段及口径

每个 session 至少需要：

```text
session_id（非身份编号）:
版本 SHA/设备/系统/浏览器/屏幕尺寸/操控手:
首次接触？ / 幸存者经验？
战斗总用时、真实总局长（包含选卡）:
每波结束时：击杀、XP 等级、四武器等级、生命、战术卡:
每一次 XP 升级：游戏秒数、波次、连续弹窗数量、候选三选一、选择理由:
每次进化：前置卡、武器 Lv.5 到达时刻、进化完成时刻:
死亡或胜利：敌种/波次/位置、是否看见预警、认为公平否:
站桩→撤离至少一个典型时刻:
明显卡顿/输入丢失/设备发热:
玩家能复述的奖励与前置条件:
玩家是否自行再次点击“出击”:
待验证问题 / 观察证据 / 观察员假设（三者分开）:
```

**隐私**：不采集姓名、手机号或个人身份数据；录像需征得试玩者同意，默认只使用文本记录。

## 5. 最小版本门槛（Go/No-Go）

| 门槛 | 可执行标准 | 结果状态 |
|---|---|---|
| G01：可靠运行 | 无开局失败、失控、卡死、升级卡无法选、结算后不能重开等真实 P0 | **待测** |
| G02：首局上手 | 10 人样本下至少 8 人能独立完成移动+自动攻击；不足 10 人如实记原始人数 | **待测** |
| G03：升级理解 | 至少 8/10 理解局内升级和波后卡不同；能说出一个进化前置条件 | **待测** |
| G04：主动重开 | 至少 6/10 在不被提醒的情况下自行再开一局 | **待测** |
| G05：后期可玩 | Android、iPhone 均能正常输入，后期中端机不长期低于 30FPS | **待测** |
| G06：战术选择 | 至少 7/10 能描述一次站桩、撤离或构筑选择的理由 | **待测** |
| G07：进化通路 | 四条进化配方在受控条件下均可完成；正常玩家至少有现实机会完成一条 | **待测** |

这些是产品设计的**暂定方向性阈值**，小样本没有统计显著性意义。任何 G01 失败或高频不公平死亡问题，优先修 M5.2，暂缓 M6。

## 6. 决策树：先修哪里

```text
试玩结束
├─ 出现真实 P0 / 手机长期无法操作？ → 先修可靠性、触控与性能
├─ 上手或升级规则明显不理解？      → 修教程、卡面文案、层级提示
├─ 连续升级频繁打断爽感？          → 探索合并升级展示/升级节奏调参
├─ 进化完成率太低？                → 检查 XP 阈值、配方入池/选择机会
├─ 玩家只绕圈，缺目标感？          → M6.0 单一“可选孵化虫巢”最小试验
├─ 玩家不愿主动重开？              → 分析反馈、局长、内容差异再定 M6/M7
└─ 体验门槛全部过线？              → 正式立项 M6.0；M7 可做经济设计校准
```
