# RFC：无尽虫潮 — 微信小游戏优先的 Cocos Creator 迁移路线（v1.0）

> **文档状态**：技术规划 / 待 PoC 验证，不代表已迁移或已发布  
> **编写日期**：2026-11-12  
> **产品平台优先级**：微信小游戏（主）→ Cocos Web Mobile H5（试玩/测试）→ 其他平台（以后再评估）  
> **拟选引擎**：Cocos Creator **3.8 LTS**，实施时锁定经验证的具体 3.8.x 补丁版本；TypeScript  
> **呈现路线**：预渲染 3D 素材制作 **2.5D 斜俯视效果**，战斗仍使用 2D 逻辑平面  
> **原则**：**先验证、再迁移；保留玩法核心、重建表现层；新旧并行、主干不停工；不提前声称上线成功**  
> **文档性质**：独立的工程迁移 RFC，**不替代** PRD v2.5，不触及既有 main 运行与部署流程。

## 0. 执行摘要与非目标

### 0.1 建议的工程决策

1. 正式版 **优先选 Cocos Creator 3.8 LTS**，共享 TypeScript 规则模型；Cocos 的同一工程构建 **WeChat Mini Game** 和 **Web Mobile**，避免长期维护 Phaser/Cocos 两套表现实现。
2. **保留现有 Phaser 3 H5 原型**，继续为 M6 功能提供可玩验证和规则回归；在微信 PoC 通过前，**不停止主对话的功能迭代**。
3. 在独立 Cocos 迁移分支中以 **纵向切片** 推进：启动 → 操作与射击 → 真实虫潮 → 奖励/成长 → 三幕/英雄 → 局外/存档；不要先一次性搬完所有文件。
4. **2.5D 不是运行时全面 3D**：角色、虫族、武器与环境主要采用低多边形模型预渲染的方向动画/图集；继续使用平面坐标、圆形碰撞、空间查询及分层渲染。
5. 首次发版优先证明 **核心体验、长局可靠恢复、正确结算、手机触控、微信真机运行**；不要在迁移里同时加入商业化、联网、排行榜等新范围。

### 0.2 明确非目标

- 不在迁移过程中改写已经确定的 15–20 分钟 Roguelite 三幕愿景、四普通武器槽 + 独立英雄级专武槽、无强制 XP 弹窗、局外战区/素材/装备方向。
- 不将 Phaser 场景或 Phaser Sprite 直接当作 Cocos 组件搬运；**只有无引擎依赖的规则代码才可能直接移植**。
- 不为迁移立即建设付费、实时联机、复杂后端、全实时 3D、物理引擎驱动的千虫碰撞。
- 不自动替换 https://kk518.top/swarm/ 的现网内容，不自动合并本 RFC 所在分支。

### 0.3 产品需求优先级

1. 玩家已确认的产品支柱：**每局新鲜 / 失败也爽 / Build 上头**；单指移动、自动开火、停步展开；连续战斗无频繁 XP 弹窗。
2. 目标完整局 **15–20 分钟**，三幕九遭遇、幕间约 6–10 次有意义抉择；波内 XP 自动小成长。
3. 英雄被动 + 英雄专武 + 至多 **4 个普通武器槽**；扩展优先真实行为差异，不允许仅注册内容数据就宣称可玩。
4. 战区选择（钢铁遗迹/感染巢穴/雷暴前哨）→ 地区资源 → 装备工坊/科技/底盘；失败也带回部分进展，结算幂等。
5. **现状与规划必须分开描述**：上面是目标需求，不表示现在的 main 已实现所有系统。

## 2. 引擎 ADR：为什么是 Cocos Creator，什么时候允许推翻

| 维度 | Phaser 3（目前） | Cocos Creator 3.8 LTS（目标） | 判定 |
| --- | --- | --- | --- |
| 微信小游戏构建 | 需自行维护兼容方案 | 有官方微信发布工作流 | **Cocos 有优势** |
| Web Mobile 试玩 | 现成且稳定 | 由同一 Cocos 工程构建 | 正式版 H5 使用 Cocos |
| 2.5D 精灵/图集 | 可做 | 可做，Prefab/动画/材质编辑更完整 | Cocos 更利于内容规模化 |
| 未来有限 3D 能力 | Phaser 不适合 | Cocos 具备 3D 能力 | 不是首版采用实时 3D 的理由 |
| 当前规则复用 | 几乎无需迁移 | 纯 TS 规则可复用，表现不可直接复用 | 需分层 |
| 当前迁移代价 | 无 | 非零且集中在场景/UI/渲染/音频/构建 | 必须先做 PoC |

**决策门槛**：Cocos 先验证微信真机启动、资源加载、帧稳定性和 Core 集成；验证失败先排查构建/版本/资源流程，若成本不可接受再讨论 Phaser 适配或其他引擎，不能因“理论上支持微信”直接全量迁移。

**版本策略**：只选一个通过微信 Android+iOS 测试的 `3.8.x` 编辑器与引擎版本，并在仓库文档/构建器中固定；补丁更新先走冒烟验证，避免“编辑器一升级全员工程元数据变化”。

## 3. 目标代码与运行时架构

```text
微信小游戏 / Cocos Web Mobile
          │
          ▼
Cocos App（Scene、UI、Prefab、动画、2.5D Presenter）
          │ InputAdapter / AudioPort / AssetPort / StoragePort
          ▼
Application / RunController（流程、生命周期、暂停恢复）
          │ commands                        ▲ events + readonly snapshot
          ▼                                 │
GameCore（纯 TypeScript、无引擎 API） ───────┘
  ├─ FixedStep / WorldState / Collision / SpatialGrid
  ├─ EnemySystem / TargetSystem / WeaponSystem / HeroSystem
  ├─ Roguelike / Reward / AutoGrowth / CampaignDirector
  ├─ Battlefields / MetaProgression / Settlement
  └─ SeededRandom / SnapshotCodec / SchemaMigration
          │
          ▼
Platform Adapter（微信 / Web）
  ├─ LocalSave 与可选 CloudSave（后期）
  ├─ Lifecycle / Sound / Network / Logger
  └─ Publish / Share / Login（按版本接入）
```

### 3.1 规则、流程、表现边界

**GameCore 只允许**普通 TypeScript 数据、纯函数和受控状态更新。不能 `import 'cc'`、`import 'phaser'`、读取 `window/document/wx`、创建 Sprite、请求网络或直接播放音效。

- **输入**：Cocos 摇杆输出标准 `MoveIntent{ x, y, pressed }`；核心按固定步长消费并更新位移。禁止用设备触控像素直接当地图坐标。
- **模拟**：核心 `step(fixedDeltaMs, commandBatch)`；按稳定顺序执行移动 → AI → 索敌 → 武器 → 命中 → 击杀 → XP → 事件。随机数由可序列化的种子流注入，不由 `Math.random()` 决定核心对局。
- **输出**：`WorldViewSnapshot`（轻量只读实体/状态数组）和有唯一编号的 `GameEvent`（播放效果、伤害数、音效、奖励等）。
- **表现**：Cocos `BattlePresenter` 接收快照并复用 Sprite/Node；`EffectPresenter` 消费事件，不反向修改核心 HP/EXP。
- **流程**：`RunController` 是唯一的战斗暂停/奖励/结算状态机拥有者，防止 UI 与 Cocos 场景各自计算奖励或波次。
- **输入适配与射击**：继续零攻击键，移动时自动开火，停步 0.8s 进入展开；绝不因移植把英雄技能变成额外手动按钮。
- **后续调用接入**：Hero/Weapon Runtime 在 Core 中只通过命令与事件驱动。`driverId` 是行为 ID，不是 Sprite/Prefab 路径；不完整驱动不可加入可用池。

### 3.2 仓库目录：目标而非立即执行的重排

**关键注意**：Cocos 3.8 的自定义工程脚本发现、外部 TS 包导入、`.meta` 资源 UUID 维护与 Node 单测运行路径，**不是光写目录结构就自动兼容**。第一阶段必须证明 `packages/game-core` 可从 `clients/cocos` 使用；若编辑器无法稳定导入外部源码，采用**单一 canonical Core + 构建时确定性复制/打包到 Cocos 可识别的 `assets/scripts/generated`**，并加 checksum 防止双份规则分叉。不要依赖未验证的符号链接或在编辑器外手改 `.meta`。

**迁移顺序**：先以现有单文件规则直接测试 Cocos 编译，再提取 Core；PR #7/#10 合并后按当时 main 的文件路径做迁移清单，避免旧路径与新模块冲突。

## 4. 现有功能到新系统的逐项迁移映射

| 迁移域 | 复用输入 | 新落点 | 主要工作 | 主要验收 |
| --- | --- | --- | --- | --- |
| 战斗数值与自动索敌 | combat/visibility/pressure | Core Combat + Target | 保留选择阈值、发射速率、展开倍率、可视目标规则 | 固定 seed 事件/结果一致或差异有解释 |
| 玩家移动与摇杆 | GameScene + main | Cocos InputAdapter | 触摸 ID、死区、设备旋转、失焦松手、双端坐标 | 单指左右手可连续移动/停步 |
| 虫潮生成与 AI | GameScene + pressure | Core EnemySystem | 从渲染实体剥离位置/生命/生成；近邻查询 | 大量虫追击/警告/死亡正确 |
| 多武器 | progression/arsenal/weaponRuntime | Core WeaponSystem | 四普通槽+一专武；驱动/数值/动画解耦 | 散射/电弧/喷火/步枪均可击杀 |
| 英雄与被动 | contentCatalog/heroRuntime | Core HeroSystem | 真实 passive hook；未完成英雄不可出战 | 不改变旧 marine 数值；新增被动有测试 |
| XP 和卡牌 | autoGrowth/progression | Core Growth + Reward | 自动小升级不中断；重大幕间奖励只弹一次 | 零强制 XP 战斗弹窗 |
| 三幕/事件 | campaignDirector/runRandom | Core Campaign + RNG | 活的旧五波逐步替换为九遭遇；分支/随机流 | 阶段、奖励、恢复的确定性 |
| 2.5D 美术 | Art/Phaser 图片对象 | Cocos SpriteFrame/Atlas/Prefab | 人物/虫族/方向图集、Y排序、阴影、枪口挂载 | 前后遮挡、射击指向正确 |
| HUD、卡牌、基地 | HTML/CSS | Cocos Canvas UI | HUD、半屏选择、布局安全区、局外面板 | 微信无 DOM；点击不中断摇杆 |
| 音频/震动 | Sound/浏览器 API | AudioPort / PlatformPort | 前后台/静音/触发限制 | 反复切后台声音不叠加 |
| 资源与局外经济 | PRD 战区/工坊规划 | MetaProgression + Settlement | 地区材料、工坊成本、资源事务、版本化存档 | 一次局只结算一次，失败有合理收益 |
| 发布与运维 | Vite + GitHub Actions | Cocos 构建 + 发布阶段 | web-mobile、wechatgame 双产物、版本追踪 | 构建物可复现、现网不被覆盖 |

### 4.1 迁移中最容易遗漏的“隐形行为”

- **可见虫潮**：M5.3 的镜头/索敌/生成配合是体验规则，不是“视觉细节”。新摄像机改变可见宽度后必须同步调整有效索敌距离与刷怪预警。
- **站桩火力展开**：状态判断依据有效输入而非角色是否被墙卡住；移动同一逻辑步取消展开。
- **自动 XP**：M5.2 取消频繁战斗升级弹窗；不能将历史 M5.0 弹窗行为从 `main.ts` 顺手移植过来。
- **随机一致性**：`runRandom` 的 combat/rewards/events/visuals 隔离必须保留；画面粒子随机不允许消费战斗/奖励随机流。
- **武器上限**：四普通槽与一专属槽独立；“目录里登记”不等于“有真实射击驱动并可上阵”。
- **生命与弹幕**：不得用全量 2D/3D 物理碰撞替代已有自定义判定，避免虫潮规模改变玩法手感。
- **重开与长局**：结算后释放事件订阅、对象池状态、临时 Buff、随机流和摄像机追踪；不能跨局污染。
- **高压和可读性**：降低粒子/装饰的方案不能降低敌方致命技能预警的识别度。

## 5. 2.5D 视觉方案与美术生产规范

### 5.1 首版明确的技术取舍

选择 **2D 世界 + 斜俯视图像**，而不是把世界坐标切换为 3D X/Y/Z。物理战斗坐标仍是 `(x, y)`；渲染只负责绘制有高度感的 Sprite。摄像机视口和渲染比例是表现属性，不改变碰撞、索敌、伤害距离。

- **英雄**：Blender 原创 Low Poly 机甲，统一相机方位、灯光、材质规范，导出 8 方向移动/待机/射击/受击/死亡序列帧；武器原则上拆成枪口/挂件层，允许自动瞄准。
- **虫族**：统一的脚底锚点、方向、阴影尺寸、尺寸等级；精英/自爆/喷酸与普通虫必须形体可区分，而不只变色。
- **战场**：地板、掩体、虫巢、环境警告采用可拼接 2D 美术；保留区域目标的功能轮廓与交互优先级。
- **空间遮挡**：`renderDepth = footY + layerOffset`（最终比较时通过整数层/归一化 y 处理），不是直接拿图片中心 Y 排序；投射物、地面特效和头顶 HUD 各有稳定渲染层。
- **阴影/高度**：独立地面椭圆阴影、短高度偏移、飞行弹道/爆炸视觉偏移；伤害判定不被美术跳跃/抖动污染。
- **图集规范**：统一方向顺序、帧率约定、透明边距/脚底 anchor、单位世界尺寸、命名规则（heroId/action/direction/frame）；所有打包生成有版本与来源元数据。

### 5.2 优先级与风险

先做 **1 位基础战士 + 1 工虫 + 1 步枪 + 1 场景地板 + 2 个动作** 的 2.5D 可玩样板。验证清楚后再做三英雄、六武器、Boss/精英、所有方向动画和多战区。

完整的 8 方向 × 多动作 × 多英雄/虫种会让 Atlas 迅速膨胀；必须在 PoC 中对比 **4 方向/8 方向、分辨率、序列帧数、资源大小/解码耗时/内存**，不能提前宣称“8 方向一定足够便宜”。

**美术和构筑扩展接口**：`heroId / weaponId / enemyKind / skinId` 到 Prefab/Atlas 的映射应是资源目录数据，而不是写死在 Combat/Progression 中。

## 6. 微信小游戏运行、存储与包体策略

### 6.1 平台能力适配边界

- 微信小游戏不是普通 H5：入口/生命周期、触摸、音频、存储、网络、分享/登录应通过接口适配；禁止把 `window.document`、DOM、localStorage 当成 Core 的全局依赖。
- `StoragePort`：`load/save/remove`，包含写入结果与错误处理；Web 使用浏览器存储适配器，微信使用平台存储接口。**两边存档不会自动互通**。
- `LifecyclePort`：前后台/中断；暂停战斗逻辑时间、释放按压状态、恢复后不补算隐藏期间的 delta。进入微信电话/锁屏/应用切换要实测。
- `AudioPort`：BGM、射击短音效、音量、静音、失焦恢复，音频实例/事件监听成对释放。
- `PlatformPort`：仅对微信专属登录/分享/必要网络端点做代理；默认不在 Core 写 `wx` 调用。
- `Logger/Crash`：初期本地日志 + 统一错误码；远程日志及用户数据上报需单独做隐私审查与授权。

### 6.2 包体 / Asset Bundle / CDN

依据 Cocos 3.8 文档所载**当时**约束：微信小游戏 **主包 ≤4 MB、总分包 ≤30 MB**（发布时应重新核对官方平台规则）。微信环境 **不能通过远程 CDN 下载执行脚本**；远程资源需要版本、缓存、合法域名与网络故障处理。

| 层 | 规划资源 | 加载点 | 失败应对 |
| --- | --- | --- | --- |
| 主包 / 首屏 | 必需脚本、启动流程、最小启动界面 | 游戏入口 | 无法进入则可重试/诊断 |
| 按需本地分包（确有必要时） | 频用基础关卡/共用资源 | 进入战区前 | 显示加载与失败可重试 |
| 远程 Asset Bundle | 战区主题、英雄皮肤、较大的动画图集与音效 | 大厅或选战区时预载 | 缓存命中/降级美术/回大厅 |
| H5 Web Mobile | Cocos 静态产物和远程资源 | Nginx / CDN | 缓存版本和回滚策略 |

**不允许**远程运行时脚本热更新规避微信包体要求。`Asset Bundle` 的代码与资源归属必须通过构建产物验证；远程 Bundle 中的脚本由 Cocos 构建流程处理，不等于“可远程执行 JS”。

首版资源设计原则：**首屏小、战场按需加载、可重试、可回滚、可量化**。建立脚本/纹理/音效/bundle 字节预算表、启动网络请求统计、加载错误率、首屏与入场耗时记录；数值阈值以真机测量设定，不拍脑袋填绝对指标。

### 6.3 游戏数据与云端的分阶段策略

- **迁移 PoC**：本地存档仅放设置/调试状态；不接账户、不接支付。
- **正式成长系统接入**：`SaveEnvelope` 带 `schemaVersion`、`contentVersion`、`profileId/localDeviceId`（如有必要）、已结算 `runId`、资源库存、装备、解锁、最后安全节点；字段验证与异常回退必须可测。
- **长局快照**：只有在“幕间/安全节点”写完整 Core 快照（Director、RNG 四流、构筑、HP、阶段选择和奖励索引），严禁保存 Cocos Node、Phaser Sprite 或函数引用；允许中途后台返回或重进恢复。
- **永久资源和战斗临时状态分离**：重开不会清空局外资源；旧快照升级必须通过 `migrateSave(vN)`。
- **结算幂等**：一次对局唯一 `runId`；`settledRunIds` 或等效事务记录；所有战备与地区材料一次性提交/持久化；中断/重复点击不会重复领资源。
- **跨设备与可信经济**：上线前需单独决策是否启用微信登录+服务端权威存档。**单纯本地客户端存档不具有防作弊或跨设备一致性**；如果规划云存档，应设计服务端鉴权、资源结算和冲突解决。不要在此次渲染迁移中默认建设完整后端。
- **历史 H5 存档**：旧浏览器 `localStorage` 与微信小游戏本地数据隔离；若要让老试玩数据迁到微信，必须单独设计用户授权/身份绑定或一次性导入，不能假定自动互通。

### 6.4 平台合规与上线前置

上线前另建清单核实：小游戏主体与 AppID、版本审核与发布规则、游戏类目/经营资质要求（如适用）、隐私告知、用户信息与数据保留、域名/HTTPS/下载白名单、素材授权及原创 IP、音效与字体授权。本文**不对当前具体主体的发行资质作未经核查的断言**。

### 7.3 G2 — GameCore 解耦拆分节奏

1. 不改业务值，先增加 **确定性行为测试**，把五波/自动 XP/卡池和武器的真实数值固定为可回归基线。
2. 抽出 **实体快照/世界状态**；一开始仍可由 Phaser 旧渲染读取同一个只读快照，减少双系统偏离。
3. 抽出 **敌人生成/攻击/碰撞**，禁止 core 创建 Phaser GameObjects；图形与音效由事件监听器播放。
4. 接入 **CampaignDirector + SeededRandom 四流**、`HeroRuntime` 与 `WeaponRuntime`，不复制旧一份新一份规则；补完整 replay 和快照测试。
5. 迁出 **奖励/成长/补给/连杀/结算**，用纯状态事务处理卡池和金币，避免 UI 点击即直接改场景对象。
6. 先双端运行 **同一套 Core**，再把 Cocos 画面升级为正式美术。旧 Phaser 原型的测试在迁移窗口仍要通过。
7. 对于经验证的差异（如视口影响生成/索敌），补 ADR/测试并经产品确认，不能无痕改数值。

### 7.4 G3/G4 — 最小可玩 parity 与美术验证

- 首先完成 “一位战士/一张图/一把枪/一种虫” 10 分钟连续试玩，再扩到四把武器/多敌种/Boss。
- 优先实现正确的 **脚底锚点、遮挡、镜头跟随、远程预警、玩家可见攻击目标**，再增加粒子与镜头震动。
- 核心要验证“停步更强”不会因图片动画/坐标转换误判；击杀数/经验/弹数与规则必须一致。
- 保留工作流：每新增一种武器/虫族，必须同时有“配置+真实驱动+资源映射+自动化/人工验收”；禁止空内容进入抽卡池。

### 7.5 G5/G6 — 长局/局外系统与发布准备

- M6 三幕九遭遇和安全节点快照优先于更多英雄/皮肤；15–20 分钟长局必须能从安全节点恢复。
- 首批三英雄（凯恩/灰烬/伊芙）、独立专武与两条融合作为 M6.2 的**目标内容**，不是迁移的先决条件；允许先用基础战士完成引擎迁移。
- 战区和工坊按 M6.1/M7 拆批：先两战区+两资源+两装备槽，再三战区/科技/底盘；规则内容与渲染迁移独立验收。
- 收集首屏加载、资源失败、崩溃、恢复失败、错误结算的真机数据；正式上线之前至少一轮 Android/iOS 微信体验版回归。
- 旧 H5 保持稳定至 G7 切换；Cocos H5 先部署到 **独立测试路径**（例如 `/swarm-next/`，最终路径部署前再确认），不覆盖当前 `/swarm/`。

## 8. CI/CD、分支与协作协议（与正在进行的主对话隔离）

### 8.1 分支方案

- `main`：现网和主对话的已验证代码；**迁移分支不自动提交/强推 main**。
- `docs/wechat-cocos-migration-rfc-20261112`：**仅本文档**，可通过 Draft PR 审阅，绝不自动合并。
- `feature/cocos-wechat-poc`：新 Cocos 最小工程验证；不修改 Phaser 线上入口/发布路径。
- `feature/core-extraction-*`：按单一系统拆 core，按最新 main rebase/merge（选一类策略并保持可审阅）。
- `feature/cocos-vertical-slice-*`：玩法切片完成后再扩视觉/场景。
- Cocos 迁移代码每个 PR 小步、依赖关系明确；独立分支上持续构建，不把正在开发的 M6 代码长期复制成孤岛。

**同步策略**：PR #7/PR #10 与后续主线落地之后，以 **commit SHA + 导出规则 API** 同步。每次迁移分支更新都运行 Core 回归并记 “同步了哪个主干 SHA”；引擎迁移不自行重新定义已确定的英雄、武器或三幕数据。

### 8.2 构建与交付流水线

1. **PR 阶段**：Node 规则单测/类型检查 → Cocos 资源/编辑器元数据校验 → Cocos Web Mobile 构建 → 微信小游戏构建（可优先手动触发/专用 runner）。
2. **Cocos 构建机**：使用已安装并固定版本的 Creator，使用 **Cocos 官方 CLI/导出的 Build Panel JSON 配置**；不能用 `vite build` 替代。CI 执行环境/授权/登录状态需实测；可先用自托管 runner。
3. **验证产物**：记录 Git SHA、引擎补丁版本、资源 manifest、构建时间、包体字节数、资源 bundle 清单。构建日志+可下载产物作为审阅证据。
4. **Web Mobile 测试发布**：独立 Nginx 路径；禁止覆盖现有 `https://kk518.top/swarm/`。H5 路径和静态资源 base URL 需单独验证。
5. **微信体验版**：构建→开发者工具导入→体验版/真机测试→正式审核由发行负责人控制；上传凭据仅放受保护的 CI Secret/本地配置，不提交到仓库。
6. **发布**：版本化远程资源先上线且保留旧版 → 微信提审/发布 → H5 切换 → 监控首屏与存档故障 → 可回滚到旧包/旧资源 manifest。

官方 CLI 文档中成功退出码为 **36**（而非常规 0），实现 runner 时要按实际 Creator 版本/构建日志校验并明确处理，不可仅用普通 shell “0 表示成功”的假设。

### 8.3 双跑与切换原则

- **仅在迁移期双跑**：Phaser 旧版用于玩法比对和稳定在线试玩；Cocos 新版独立测试。
- **最终只维护一套正式表现**：Cocos 完成微信+H5 后，将 Phaser 归档只用于回归/历史对照，避免永久双端重复修 Bug。
- **不得假装构建通过等于真机验收通过**。后者需要设备、版本、录像/日志和结果。
- 迁移期间任何涉及现网/Secrets/域名/AppID/正式发布的动作，必须单独确认并显式进行。

### 9.2 建议验收用例（AC）

- **AC01**：Cocos 生成 Web Mobile 和微信小游戏两个可启动产物，并记录引擎/项目 SHA。
- **AC02**：单手浮动摇杆、松手停步与火力展开触发/退出语义不变；手机旋转、失焦不粘摇杆。
- **AC03**：自动锁敌、移动开火、武器冷却、精英/补给/Boss 行为和旧版核心规则一致或差异有记录。
- **AC04**：战斗 XP 自动小升级不弹窗，幕间重大选择只发放一次，卡池不会出现无效武器。
- **AC05**：四普通武器槽 + 一独立专武槽；未注册真实攻击驱动/特效的英雄武器不可上阵。
- **AC06**：2.5D 实体脚底与碰撞点一致、前后遮挡正确、预警不会被大特效遮挡。
- **AC07**：相同 seed/命令的核心战斗与奖励结果可重复；视觉特效随机不改变卡池。
- **AC08**：长局中断重进从安全节点恢复；旧快照被明确升级或安全拒绝；不会重复结算。
- **AC09**：失败/胜利正确产出地区材料并永久保存；一次对局不能重复领奖或出现负数余额。
- **AC10**：微信远程资源加载失败可回退/重试，不导致卡死；缓存与版本切换结果可追踪。
- **AC11**：主包/分包符合当时平台限制；禁用远程脚本执行；至少两款微信真机完成关键流程。
- **AC12**：Cocos H5 使用独立测试 URL，旧 `/swarm/` 在显式批准前不变；有版本回滚预案。

### 9.3 非功能底线

目标 60 FPS、性能低谷不影响可玩操作；**具体画面预算以 Android/iOS 真机数据决定**，不把抽象帧率作为 M6 产品立项的首要门槛。不可接受：连续崩溃、长局存档丢失、重复领取资源、控制粘滞、危险预警不可见、正式包无法加载资源。

技术日志建议至少记录：引擎/资源版本、设备大类、Scene 切换、bundle 加载耗时与失败、世界活跃实体数、事件数量、战斗帧耗时、暂停/恢复次数、存档/结算结果；远程分析在隐私评审后再启用。

## 10. 风险清单与应对

| 风险 | 早期信号 | 应对与退出条件 |
| --- | --- | --- |
| 共享 TS Core 在 Cocos 中无法稳定导入 | 编辑器找不到源码/类型或微信构建失败 | G1 验证外部包；必要时 canonical Core + 可校验生成副本 |
| 迁移和 M6 并发形成两份玩法规则 | 同名系统逻辑偏差、每次合并大量冲突 | 以 PR #10 接口为单一真相，按 SHA 迁入，强制契约测试 |
| 2.5D Atlas 体积/内存增长过快 | 微信包超限、加载慢、贴图解码掉帧 | 先原型测 4/8 方向、纹理尺寸/压缩、Asset Bundle |
| Cocos 资源 UUID 或 Prefab 被错误维护 | 资源引用丢失、场景无法加载 | `.meta` 入库、编辑器管理资源、禁止人工改 UUID |
| 主包/远程资源异常 | 微信真机白屏/进度卡住 | 主包精简、合法域名、重试/回退、版本 manifest、旧版 CDN 保留 |
| 逻辑坐标与渲染坐标混用 | 站桩误触发、距离异常、敌人屏外死亡 | 统一 Input→World 转换和 CameraViewport 测试 |
| 微信后台/长局断线损坏状态 | 恢复后连发、重复结算、掉资源 | 安全节点快照、暂停 delta、结算 runId 幂等 |
| 微信本地存档作弊/无法跨设备 | 工坊余额篡改、换设备进度消失 | 上线前明确服务端存档决策；不混淆本地与可信经济 |
| 双流水线误覆盖线上 | `main` 更新触发新部署到旧路径 | H5 staging 独立、CI 保护、上线显式审批 |
| 大量重写导致迟迟无法试玩 | 只剩空目录和架构图 | G1/G3 纵向切片优先，先完成一枪一虫 |
